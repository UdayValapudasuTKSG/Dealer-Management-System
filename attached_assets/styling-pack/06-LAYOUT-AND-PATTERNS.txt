2. Sidebar (the dark navigation)
Dark slab: bg-zinc-950 text-zinc-200 , sticky top-0 h-screen , collapsible between

w-[220px] and w-[56px] with transition-[width] duration-200 .

Wordmark (serif) + a small "AI" capsule badge ( Sparkles + uppercase tracked).
Nav is data-driven from a NAV: NavItem[] array, each { to, label, icon, section } .
Items are grouped by section with tiny tracked-uppercase section headers.
Active item = bg-white text-zinc-950 (inverted); inactive = `text-zinc-400
hover:bg-white/5 hover:text-white . Active match: location === to || location.startsWith(to)`.
When collapsed: icons only, centered, title tooltips.
Footer: a user/persona switcher (dropdown-menu) with an avatar (initials), name +
role, and a sign-out item. Plus a tiny trust line ( ShieldCheck · SOC 2 ).
type NavItem = { to: string; label: string;
icon: React.ComponentType<{ className?: string }>; section?: string };

3. Persona / RBAC (multi-role from one app)
A PersonaProvider models distinct user roles, each with its own home route and allowed route prefixes. This
lets one codebase serve internal users, admins, and external portals.
type Persona = { id; name; role; icon; home: string; allowed: string[]; scope; username };
function canAccess(persona, path) {
return persona.allowed.some(a => path === a || path.startsWith(a + "/") || path.startsWith(a));
}

Sidebar filters NAV by canAccess . The shell redirects to persona.home if the
user navigates to a disallowed route.
Persona + auth flags persist in localStorage (keys are app-namespaced, e.g.
app.persona.v1 , app.auth.v1 ). Never persist raw tokens.

A persona switcher in the sidebar lets you preview the app as any role — great for demos.
Generalize: roles = whatever your domain has (operator / manager / executive / customer / admin). The
pattern (home + allowed-prefixes + route gating + switcher) is reusable as-is.
