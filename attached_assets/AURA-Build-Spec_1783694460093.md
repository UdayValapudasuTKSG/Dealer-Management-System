# AURA — Dealer Management System
## Build Specification & UX Instructions
*Internal agentic behaviour + how the user experience should be built*

> **Read this as build instructions.** For every capability there are two layers:
> **(a) User Experience** — what to build into the UI (kept deliberately minimal and calm), and
> **(b) Agentic (internal)** — what the AI does behind the scenes, which must **never be exposed in the UI**.
> The intelligence lives underneath; the surface stays simple.

---

## 0. The one rule

**Show outcomes, not machinery.** The user never sees the agent think. No confidence scores, no "AI is working…", no internal steps, no reasoning traces, no queue of automated tasks. The agent does the heavy lifting invisibly; the screen shows a finished result or asks for exactly one human decision. If a thing can be done for the user, it is already done by the time they look.

---

## 1. UX philosophy — how the experience must feel

These are non-negotiable UX instructions for the whole product:

1. **Invisible agent.** All agentic work (capture, dedupe, qualify, price, draft, route, chase, post) happens server-side and silently. The UI presents results, not process.
2. **One clear action per screen.** Whatever the user must do is isolated and pre-populated. The agent has already gathered context, validated inputs, and staged everything.
3. **Human decisions only at gates.** A person is interrupted *only* where policy requires it (money, credit, regulated filings, below-floor price, capital, access). At a gate, show a single, plain approve / adjust — with the evidence the agent assembled, not raw data.
4. **Instant by default.** Because the agent pre-computes, screens load already-answered. Quotes, payment ranges, availability, estimates appear immediately.
5. **One identity, every channel.** WhatsApp, web, walk-in and phone resolve to the same customer and the same in-progress deal. Nothing is re-typed when a customer moves channel or a different staff member picks up.
6. **Progressive disclosure.** Default to the essential; reveal detail only on request. Never dump the full data model on a screen.
7. **The agent chases; the user doesn't.** Follow-ups, reminders, SLA escalations, funding chases, document nudges all run in the background. The user sees only what needs *them*, surfaced as a task when it's actionable.
8. **Calm, quiet surfaces.** No dashboards screaming metrics at advisors; role-appropriate views only. Managers get oversight; advisors get their next action.
9. **Every automated action is reversible or gated.** If it isn't reversible, it's a human gate. This is what lets the UI stay confident and simple.
10. **Trust through receipts.** When the agent acts, the user can always see *what happened* after the fact (a clean timeline), even though they never saw it happening.

## 2. Agentic architecture (internal — never surfaced)

Every agent runs on one shared chassis:

```
event → wake the right agent → gather context (customer 360, deal, inventory, policy)
      → plan → call scoped tools/integrations → POLICY ENGINE (the 4 questions)
      → if clear: execute + emit events + write audit
      → if gated: assemble evidence pack → surface ONE human decision → on approval, execute
```

- **Event-driven.** Every action emits a versioned event; other agents react. This is the connective tissue — one event in one domain wakes work in another (e.g. `unit.reserved` locks the VIN, notifies logistics, and updates the lead).
- **Scoped authority.** An agent acts *for* a role and inherits that role's access — it can never exceed what the human it serves is allowed to do.
- **Model routing.** Claude is the primary reasoning model; routing selects tiers by task. Grounded strictly in tenant data.
- **Memory.** Per-customer and per-deal context persists so conversations and deals resume seamlessly across channels and sessions.
- **Multi-tenant + on-prem.** Each dealership is an isolated tenant; agents are tenant- and channel-scoped.
- **Everything audited.** Who (human or agent) did what, and who approved it — immutable, for compliance.

## 3. The AI agent workforce (internal behaviour)

Twelve agents. For each: when it wakes, what it does invisibly, the systems it uses, how much it may do alone, and what the user actually sees.

### ◆ Concierge AI
- **Wakes on:** Any inbound enquiry (WhatsApp, Meta, web form, call) or a delivery/onboarding milestone.
- **Internal job:** Owns the customer conversation. Merges every channel into one identity, answers instantly from tenant knowledge + live inventory, qualifies lightly, and keeps the lead status current. At delivery, drives digital onboarding.
- **Systems/tools:** Twilio (WhatsApp/SMS/Voice), Meta, web-to-lead, knowledge base, inventory service, OEM app/telematics.
- **Autonomy:** High. Sends messages, answers, books — but every outbound external message is drafted-then-sent under HITL where the tenant requires review; low-confidence answers hand off to a human.
- **What the user sees:** The customer sees instant, human-sounding replies. Staff see a fully-formed lead with transcript; they never re-key.

### ◆ Sales AI
- **Wakes on:** Lead becomes ready-to-shop; advisor opens a deal; customer configures online.
- **Internal job:** Assembles the deal. Builds cash/finance/lease scenarios penny-accurate, generates the auto-quotation from the pricing master, keeps the online↔in-store deal in sync, manages VIN lock and order lifecycle.
- **Systems/tools:** Pricing master, quotation engine, desking tool, inventory, deal store.
- **Autonomy:** High for construction and math; below-floor pricing and discounts beyond threshold pause for a manager.
- **What the user sees:** The advisor sees ready-made options; the customer sees identical numbers online and in-store.

### ◆ Appraisal AI
- **Wakes on:** Customer starts a trade-in (photos) or advisor requests an appraisal.
- **Internal job:** Grades condition from photos with vision, estimates reconditioning, pulls market comps, proposes an ACV range.
- **Systems/tools:** Vision service, market data.
- **Autonomy:** Proposes only. The final trade value that moves money is always a human confirmation.
- **What the user sees:** The customer photographs the car; a clear number comes back after a human confirms it.

### ◆ Finance AI
- **Wakes on:** Deal agreed; documents needed; financing chosen.
- **Internal job:** Runs the regulated room. Builds the exact document checklist, OCR-validates uploads, runs soft-pull pre-qual, routes the application to the lender (Demerara Bank LOS), presents the compliant protection menu, sequences disclosures for e-sign.
- **Systems/tools:** F&I portal, OCR, credit bureau, Demerara Bank LOS, DocuSign, ERPNext.
- **Autonomy:** High for assembly and routing; declines, non-standard terms, adverse action, and funding release are human.
- **What the user sees:** The customer uploads documents once and sees a real payment range; the F&I manager only touches decisions the law requires.

### ◆ Inventory AI
- **Wakes on:** Unit acquired; stock aged; pricing due; a wanted unit is out of stock.
- **Internal job:** Runs stock. VIN intake, AI photos/description, publish-when-ready, market-tested pricing (auto within band), stock-mix recommendations, inter-store locate, remarketing.
- **Systems/tools:** Inventory service, merchandising, pricing engine, storefront, dealer network.
- **Autonomy:** High for merchandising and in-band repricing; capital orders and floor prices are human.
- **What the user sees:** Customers see accurate live stock; managers approve only orders and floors.

### ◆ Customs AI
- **Wakes on:** Order approved; vehicle in transit; arrival at port.
- **Internal job:** Runs the Guyana import chain. Places/tracks orders, coordinates freight, captures dual-currency landed cost, computes GRA duty on the versioned schedule, assembles the clearance and registration packs.
- **Systems/tools:** Order mgmt, logistics, duty engine (GRA schedule), customs portal, registration, ERPNext.
- **Autonomy:** High for computation and pack assembly; the GRA filing itself is done by a responsible officer.
- **What the user sees:** The customer waits with nothing to chase; duty reprices itself on a budget change.

### ◆ Scheduler AI
- **Wakes on:** Test-drive request; service booking; delivery readiness.
- **Internal job:** Owns every calendar. Books against real demo-fleet / bay / technician / parts availability, prevents double-booking, sends reminders, runs delivery-readiness checks and loaner assignment.
- **Systems/tools:** Calendars (demo/bay/tech/parts), Twilio reminders, loaner fleet, delivery board.
- **Autonomy:** High. Booking, reminding, readiness-gating are automatic; final delivery go is a human.
- **What the user sees:** The customer picks a slot that is genuinely available; no-shows drop.

### ◆ Service AI
- **Wakes on:** Vehicle checked in; inspection done; RO to close.
- **Internal job:** Runs fixed ops. Turns the technician's inspection into a media estimate, sends it for line-by-line approval, builds warranty claims, invoices and closes the RO.
- **Systems/tools:** DVI, diagnostics, warranty (OEM claims), payment gateway, ERPNext.
- **Autonomy:** High for estimate/claim/invoice assembly; QC sign-off and high-risk warranty are human; the customer approves the work.
- **What the user sees:** The customer approves work on their phone with photos and prices; only approved work happens.

### ◆ Parts AI
- **Wakes on:** Work approved; stock threshold hit; obsolescence sweep.
- **Internal job:** Runs the parts chain. Forecasts demand, auto-replenishes within threshold, stages parts for approved jobs, files OEM returns.
- **Systems/tools:** Forecasting, purchasing, warehouse, supplier APIs.
- **Autonomy:** High within thresholds; large purchase orders are human.
- **What the user sees:** Technicians never wait for parts; the parts advisor approves only large buys.

### ◆ Ledger AI
- **Wakes on:** Deal funds; RO/parts sale closes; period end; refund to post.
- **Internal job:** Runs accounting. Posts deals/service/parts to ERPNext penny-perfect, three-way AP matching, continuous close, commission/payroll feeds, refund receipting.
- **Systems/tools:** ERPNext (GL, AP), payroll feed.
- **Autonomy:** High for posting and matching; every payment run and the close are released by a human.
- **What the user sees:** Back office shrinks; money only ever leaves on a human's authority.

### ◆ Retention AI
- **Wakes on:** Lead not ready; delivery complete; equity beats payoff.
- **Internal job:** Runs lifecycle. Drives the 4-call cadence, nurtures and wins back, sends post-delivery thank-you + survey, spots upgrade equity and drafts the next offer.
- **Systems/tools:** Nurture engine, Twilio, campaign studio, equity model.
- **Autonomy:** High for cadence and nurture; offer economics and campaigns are approved by marketing.
- **What the user sees:** The customer gets timely, relevant contact — never spam; managers approve the economics.

### ◆ Analyst AI
- **Wakes on:** A question is asked; a KPI moves; a period closes; any AI action fires.
- **Internal job:** Runs BI + governance. Answers plain-language questions role-appropriately, monitors KPIs, compiles reports, and enforces the policy engine + immutable audit on every agent action.
- **Systems/tools:** Analytics, semantic layer, dashboards, policy engine, audit ledger, Google SSO.
- **Autonomy:** High for analytics and logging; role/access changes are human.
- **What the user sees:** Anyone asks their data in words; every automated action is logged and governed underneath.

## 4. Autonomy & governance (internal)

**The 4 questions — the policy engine runs these on every agent action:**
1. Is it **irreversible**? 2. Is it **regulated**? 3. Is it **material** (moves real money)? 4. Is confidence **low**?
If any is *yes*, the action pauses for the right human. Otherwise it executes automatically and is logged.

**The never-list — permanently human, never automated:**
1. Releasing money (refunds, payment runs). 2. Adverse credit / decline decisions. 3. Submissions to GRA. 4. Selling below the pricing floor. 5. Capital commitments (stock/PO orders). 6. Changing what the AI itself is allowed to do (roles/access) — plus a always-available kill switch.

**Autonomy ratchet.** Start conservative (agents propose, humans approve broadly), then widen to banded thresholds as trust is earned, then to exception-only. The UI never changes — only how often a gate appears.

**Kill switch + audit ledger** are always on. Any human can stop an agent; every action is permanently recorded.
