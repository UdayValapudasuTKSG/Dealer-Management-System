# Layer 9 — Cancellation & Refund Sales Manager / Finance

**🚦 Flow (step-by-step, lowest level)**

- **1. Initiate cancellation.** Sales user opens the deal/booking in the Workflow console and clicks the single secondary CTA `Cancel & Refund` (the primary CTA is always `Advance to {stage}`). A modal loads a **config-driven cancellation reason picklist** (from `lead_sources`-style admin config; see Key fields). Requires `reasonCode` + free-text note.
- **2. Guard note text.** The free-text `reasonNote` and any customer-supplied WhatsApp/email cancel request are passed through `guardUntrusted()` before persistence and before any AI summarization — untrusted text is never executed as instruction.
- **3. Refundability check (deterministic, server-side).** Server evaluates **refundable-until-registration** rule: refund is allowed only while the linked `deliveries.steps.registration` step is NOT completed (i.e., no GRA registration filed / no plate assigned). If registration done → refund path blocked, only goodwill/manual path (Approvals gate) remains.
- **4. Money gate raised.** If any funds were captured (`bookings.amountPaid` > 0, or `deals.depositPaid`/`payments` exist), server creates a `gates` row `type=refund_release` in `pending`, attaching `evidence[]` (payment ids, receipt ids, invoice status, refundable window computed). No money moves yet.
- **5. Manager approval (Approvals, not Readiness).** Sales Manager opens Gates queue, reviews computed refundable amount + retained fees, then `POST /gates/:id/resolve` with `resolution=approved|rejected`. This is the **Approvals** disambiguation of "Review", distinct from stage Readiness check and AI Approve/Override.
- **6. Finance executes refund.** On gate approved, Finance records the refund via `POST /payments` as a **negative/refund-method ledger entry** against the invoice, sent with an `idempotency_keys` token. Server recomputes invoice status (→ `partially_paid`/`void`) and issues a refund `receipts` row. NO external payment gateway — internal ledger only.
- **7. Release inventory.** Server cancels the reservation: `bookings.status=cancelled`, clears vehicle **soft-lock** (`vehicles.holdUntil`/`holdReason` nulled) and sets `vehicles.status=available` (unless another active booking/deal holds it). Deal moves to `cancelled`; delivery (if auto-created) is voided.
- **8. Retain history.** Lead is NOT deleted — `leads.status=cancelled`/lost with `lostReason`; all `timeline_events`, quotes (superseded), payments, receipts, gate resolution retained for audit. `recordAgentRun`/`audit-logs` capture the release.
- **9. Notify.** Notification + customer comms fired: internal `notifications`/`tasks` to owner & manager; customer refund confirmation queued to `email_logs` outbox (email + WhatsApp) with dedupeKey.
- **10. Multi-interest cancel-one.** If the customer had multiple interested vehicles / multiple bookings, only the selected `bookingId`/`dealId` is cancelled and released; sibling interests, quotes, and the parent lead remain active.

**⚙️ Agents in play**

- **A7 Outreach composer** → trigger: cancellation recorded → grounded inputs: `leads` row, `bookings.reasonCode`, `customers.loyaltyTier`/`lifetimeValue`, retained-fee amount (never the raw money math — server supplies numbers) → output shape `{headline, riskLevel, actions[], draftMessage}` via `GET /leads/:id/agent-brief` (e.g. win-back or refund-empathy draft) → **HITL: YES** — human "Approve & Send" via `/outreach` or `/whatsapp`; never auto-sends. Confidence below `MIN_AGENT_CONFIDENCE` → no draft, routed to human.
- **A6 Call sentiment** → trigger: if cancellation captured from a call note → grounded inputs: `call_logs` note text (wrapped in `guardUntrusted`) → output: `sentiment` tag on the note → **HITL: fire-and-forget + manual** `/suggest-sentiment`; declared, audited via `recordAgentRun`, kill-switchable via `agents.status`.
- **No autonomous money agent.** Refund amount, retained fees, and tax reversal are computed **deterministically server-side** from `dealer_taxes`/ledger — the model NEVER invents refund figures, TIN, VIN, or duty. AI only drafts human-facing prose.
- **Kill-switch + audit.** Every agent call here checks `isAgentEnabled`, PII-minimizes inputs, and writes `agent_runs` (runType, inputSummary, outputSummary, confidence, latency, status).

**🧠 AI for the persona**

- **Sales Manager** sees an A7 **agent-brief** on the gate: `{headline:"Refund $X, GYD equiv, within window", riskLevel, actions:["Approve refund","Offer alt-vehicle hold","Retain deposit per policy"]}` — advisory only; the Approve button is the human gate action.
- **Finance** sees a computed refund breakdown card (deposit − retained fees − non-refundable admin) with tax reversal lines from `dealer_taxes`; AI does not compute these, it only annotates ("VAT reversed on refundable portion").
- **Win-back suggestion**: A7 optionally drafts a retention message for high-`lifetimeValue`/`loyaltyTier` customers, surfaced as a draft the manager can Approve & Send.
- All monetary display shows USD-scale value × `dealer.usdExchangeRate` for GYD; dates in America/Guyana GMT-4.

**🔑 Key fields · validations · SLA**

- **Cancellation picklist** (admin config, versioned): `reasonCode ∈ {customer_changed_mind, financing_declined, found_elsewhere, price, delivery_delay, vehicle_defect, duplicate, other}`; `reasonNote` required (max 1000 chars, guardUntrusted).
- **Refundable-until-registration**: refund allowed iff `deliveries.steps.registration.status != completed` AND `vehicles.status ∉ {delivered, sold}`. Otherwise gate blocked → manual goodwill via separate Approvals path.
- **Gate** `type=refund_release`: `evidence[]` must include payment ids + invoice status + computedRefund; `resolution` mandatory; approver role ≥ sales_manager; finance sets `approvedAmount ≤ computedRefund`.
- **Retained fees**: non-refundable admin/reservation fee configurable per dealer; server subtracts before `computedRefund`. Money stored USD-scale.
- **Idempotency**: refund `POST /payments` requires `Idempotency-Key`; replay returns original receipt, never double-refunds.
- **Dealer-scope**: every query (gates, payments, vehicles, audit-logs, object-storage ACL on refund docs) scoped by `activeDealerId(res)` + `x-dealer-id`; division axis (CAM/GT) enforced.
- **SLA timers**: refund_release gate target resolution ≤ 24h (task + reminder to manager); Finance refund execution ≤ 48h post-approval; customer refund confirmation queued immediately on ledger post. Vehicle soft-lock auto-expiry (lazy) via `bookings.expiresAt` unaffected — cancel releases immediately.
- **History retention**: no hard delete; `leads.status=cancelled`, quotes → `superseded`, all timeline_events + audit-logs retained.

**🔀 Edge-of-edge cases → handling**

| Scenario | Detection | Handling | Owner | HITL? |
| --- | --- | --- | --- | --- |
| Vehicle already registered / delivered before cancel | `deliveries.steps.registration=completed` or `vehicles.status∈{delivered,sold}` | Block refundable path; **422**; route to manual goodwill Approvals gate; refund not auto-computed | Sales Manager | Yes |
| Multi-interest customer cancels one vehicle only | Request carries specific `bookingId`/`dealId`; sibling active bookings exist | Cancel + release only targeted booking/vehicle; keep parent lead + other quotes active; timeline notes scope | Sales | No |
| Two managers resolve same gate concurrently | Second `resolve` sees non-pending status | **409 conflict**; first resolution wins; second sees resolved state | System | No |
| Duplicate refund submit (double-click / retry) | Same `Idempotency-Key` on `POST /payments` | Replay returns original receipt; ledger not re-debited | System (Finance) | No |
| Vehicle held by another active booking/deal | On release, another `bookings.status=active` references same `vehicleId` | Do NOT flip to available; keep `reserved`; only clear this deal's hold link | System | No |
| Partial payment made (deposit only, invoice partially_paid) | `invoices.status=partially_paid` | Refund only captured amount minus retained fee; recompute invoice → void if net zero | Finance | Yes (gate) |
| Refund via original method unavailable (e.g. mobile_money reversal) | Method flagged non-reversible | Finance selects alternate method (bank_transfer/cheque); note reason on receipt | Finance | Yes |
| Customer WhatsApp/email cancel request (inbound untrusted) | Inbound via webhook / IMAP | Text wrapped `guardUntrusted`; A1 may create task, never auto-cancels money; human confirms | Sales | Yes |
| Refund confirmation email/WhatsApp fails / bounces | Outbox `email_logs` retry/backoff exhausted; WA delivery failed / opt-out | Fall back to alternate channel; mark `failed`; task to owner to call; dedupeKey prevents double-send | System → Sales | Yes on exhaust |
| Cross-tenant access attempt on gate/payment | `dealerId` mismatch vs `activeDealerId(res)` | **404/403**; object-storage ACL denies refund doc; audit-logged | System | No |
| Booking soft-lock already expired (lazy-expiry) when cancel fired | `bookings.status=expired` at cancel time | Skip vehicle re-release (already available); still process refund of any captured funds | System | No |
| Financing already disbursed (LOS) | `finance_applications.status=disbursed` | Block simple refund; require lender clawback via LOS + capital gate; manual | Finance | Yes |
| Gate approved but refund never executed (SLA breach) | Approved >48h, no `payments` refund row | Escalation task + reminder to Finance lead; gate stays open in dashboard | Finance | Yes |
| Negative net (retained fee > deposit) | computedRefund ≤ 0 | No refund; record cancellation, retain full deposit per policy; notify customer | Sales Manager | Yes |
| AI drafts refund figure or auto-sends | Guardrail: money from AI output | Rejected — server-computed only; A7 draft is prose, requires Approve & Send; confidence floor enforced | System | Yes |

**📄 Documents & PDF format**

- **Refund Receipt (PDF, pdfkit)** — generated on refund ledger post. Delivered via `email_logs` outbox (email + WhatsApp attachment) and stored in GCS with dealer-scoped per-object ACL. Layout: **Header** — dealer logo/name (CAM Motors / GT Automotive), division, dealer address, `receiptNumber`, refund date (GMT-4). **Parties** — customer name/account, original `invoiceNumber`, related `bookingId`/`dealId`, vehicle (make/model/year/VIN). **Line items** — columns: Description | Original Amount | Retained Fee | Refunded Amount, with tax-reversal rows (VAT/duty per `dealer_taxes`). **Totals** — Deposit paid, Less retained fees, **Net Refund (USD + GYD @ usdExchangeRate)**, refund method. **Footer** — approving manager, gate id/resolution reference, "Internal ledger — no payment gateway", cancellation reasonCode, disclaimer.
- **Cancellation Confirmation letter/email** — HTML nodemailer template `refund_confirmation`; includes vehicle released, reason, refund amount + method, expected settlement window; dedupeKey on outbox.
- **Voided Invoice** — original `invoices` PDF re-stamped `VOID`/`partially_paid` watermark; retained for audit, not re-issued to customer unless requested.
- **Gate resolution record** — no separate PDF; captured in `gates.resolution` + `timeline_events` + `audit-logs` (approver, amount, timestamp) as immutable history.
