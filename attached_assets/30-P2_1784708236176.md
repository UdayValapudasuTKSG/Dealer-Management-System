# Platform P2 — Dealer Onboarding & Provisioning Super Admin

**🚦 Flow (lowest level)**

- **Control-plane only.** This lives under `/platform/*` in the Platform Console; it is NOT dealer-scoped by `x-dealer-id`. Access requires a super-admin session with **platform:admin** (see [r4](#r4)). A dealer-workspace token here → **403** (RBAC denial); no/expired session → **401**.
- **1. Create dealer shell.** Super-admin submits legal name, region (`CAM`|`GT`), `usdExchangeRate` (~209), default divisions, initial owner-admin email. Row is written with `dealers.status=provisioning` (NC-3: create ALWAYS returns provisioning, never active). A **provisioning saga record** is created in `webhook_events`-style durable step table with per-step markers (see Key fields).
- **2. SAGA orchestration (NC-11).** Provisioning is a durable SAGA, **NOT a single DB transaction** — external calls (GCS bucket/prefix, SMTP invite, LOS Demerara enrolment) MUST NOT run inside a held DB transaction. Each step: (a) short local txn flips its marker to `in_progress`; (b) external side-effect runs OUTSIDE any txn; (c) short local txn records `done`+result or `failed`+error. Steps are idempotent and resumable; the orchestrator re-drives from the first non-`done` marker.
- **Ordered steps:** **seed_roles** (clone canonical role_permissions/role_field_permissions templates per NC-5 vocabulary) → **seed_taxes** (dealer_taxes, GRA duty is server-computed, never fabricated) → **seed_entitlements** (module + agent feature-flags per NC-9) → **provision_storage** (GCS prefix + presigned config, external) → **seed_lead_sources** → **invite_owner_admin** (SMTP, external, → email_logs outbox) → **register_los** (LOS Demerara sandbox handshake, external) → **seed_checklists** (stage_checklists + go-live checklist).
- **3. Go-live checklist gate.** Dealer stays `provisioning` (data-plane writes blocked as if not yet live; reads by owner-admin limited) until EVERY saga step is `done` AND the go-live checklist is fully checked (owner accepted invite, ≥1 division active, taxes confirmed, exchange rate confirmed, entitlements reviewed). Only then can super-admin call activate → `dealers.status=active`.
- **4. Lifecycle transitions (NC-3):** `active → suspended` (billing/compliance; NC-1 **423** blocks data-plane writes, reads still allowed) ↔ `active` (resume); `active → offboarding` (retention/export window per [r10](#r10)) → `closed`. No transition skips; illegal jump → **422** `{unmet:[...]}`.
- **Failure/rollback.** A step failure halts the saga; super-admin sees the failed marker and may Retry (resume) or Abort. Abort runs **per-step compensation in reverse** (see Edge table) and leaves the dealer in `provisioning` or moves it to `closed` — it is NEVER left partially `active`.

**⚙️ Agents / automation**

- **Saga orchestrator = deterministic SYSTEM code, NOT an LLM agent.** It is plain code with durable step markers; it is not in the NC-6 agent catalog and is not kill-switchable. No autonomous AI writer (A1 intake_dedup, A6 call_sentiment, A16 case_classifier) participates in provisioning.
- **seed_roles** clones the canonical role_permissions vocabulary (NC-5 modules: leads, customers, deals, quotes, bookings, inventory, billing, finance, deliveries, service, parts, gra, reports, dashboard, agents, communications, documents, search, settings, platform, audit) with categories view|create|edit|delete|admin and field-level hidden|view|edit templates.
- **seed_entitlements** writes per-dealer module + agent feature-flags. The agent kill-switch (`isAgentEnabled(semanticKey)`) is a platform-reserved **governance** capability (NC-13) — it is NOT grantable via `/admin/roles` and is NOT the same as **settings:admin**. Provisioning seeds default agent flags but only super-admin governance may flip kill-switches thereafter.
- **register_los** performs the LOS Demerara sandbox handshake outside any DB txn; retryable and idempotent (keyed by dealerId+attempt).
- Each external step emits a `timeline_events`/`audit_logs` entry; the invite step writes to `email_logs` (outbox) — no synchronous SMTP inside a transaction.

**🧠 AI for the persona**

- No autonomous or HITL LLM writer operates in onboarding — this is a deterministic control-plane flow. The **concierge** agent (nav-only, NC-6) may help the super-admin locate a dealer or a stalled saga step but never mutates provisioning state.
- Optional advisory: a read-only summarizer may surface "which go-live items remain" as prose, but the authoritative `{unmet:[]}` list comes from the deterministic checklist evaluator, never from the model.
- Kill-switch governance (NC-13) is surfaced here for review only; toggling agent semanticKeys (intake_dedup, call_sentiment, case_classifier, doc_prefill, outreach, test_drive_availability, pipeline_suggestions, sentiment_digest, persona_recommend, concierge, gra_extract) is a platform governance action, not a role permission.

**🔑 Key fields · validations · SLA**

- **dealers.status** ∈ {provisioning, active, suspended, offboarding, closed} (NC-3). Create → `provisioning`; go-live checklist complete + activate → `active`. No claim of a "single transaction" — provisioning is a resumable SAGA (NC-11).
- **Provisioning saga markers** (durable, one row/step): {dealerId, stepKey ∈ seed_roles|seed_taxes|seed_entitlements|provision_storage|seed_lead_sources|invite_owner_admin|register_los|seed_checklists, status ∈ pending|in_progress|done|failed|compensated, startedAt, doneAt, attempts, lastError, compensationRunAt}. External steps flagged `external:true` so the orchestrator never wraps them in a DB txn.
- **INV-SAGA-1:** no DB transaction is held across a GCS/SMTP/LOS call; each external side-effect is bracketed by two short local txns (claim → record). **INV-SAGA-2:** a dealer is never `active` unless all markers are `done` and the go-live checklist passes.
- **INV-ENT-1 (NC-9):** entitlement/feature-flag gate runs AFTER RBAC in the request pipeline; a module/agent not entitled for a dealer resolves to **404** (hidden), enforced server-side, not just UI.
- **Validations:** region ∈ {CAM, GT}; usdExchangeRate > 0; ownerEmail RFC-valid; registration format `^[A-Z]{3}[0-9]{1,4}$` applies to vehicles, not dealers; all mutations require `Idempotency-Key` (NC-7): completed replay → stored response, in-flight dup → **409**, same key + different body → **422** key_reuse_mismatch.
- **Impersonation (NC-10):** super-admin impersonation is READ-ONLY by default, time-boxed ≤60m, reason-logged, audited via `impersonatedBy`. Provisioning mutations (create/activate/suspend/close), gate-resolution, money-posting and customer-sends are HARD-BLOCKED under impersonation; writes require explicit elevation.
- **SLA:** full happy-path saga target < 60s; external steps have bounded retry with backoff; a step stuck `in_progress` > 15m raises a platform alert. Rate limiting → **429** + `Retry-After`.

**🔀 Edge-of-edge cases → handling**

| Scenario | Detection | Handling | Owner | HITL? |
| --- | --- | --- | --- | --- |
| GCS prefix created but process crashes before marker flip | On resume, marker still `in_progress`; provision_storage is idempotent | Re-run step; existing prefix reused (create-if-absent), marker → done. No orphan, no held txn | Saga orchestrator | No |
| SMTP invite fails (owner email bounces) | invite_owner_admin marker → failed; email_logs outbox status=failed | Retry with corrected email; saga pauses at this step; dealer stays provisioning | Super Admin | Yes (correct email) |
| LOS Demerara sandbox unreachable during register_los | External timeout; marker failed+lastError | Bounded retry/backoff; if persistent, super-admin may activate with LOS flagged degraded (entitlement gates finance module to 404 until healed) | Super Admin | Yes |
| Abort after storage+roles seeded | Abort requested with completed steps present | Reverse compensation: revoke LOS reg → delete invite/outbox → remove entitlements → drop seeded lead_sources/taxes/roles → GCS prefix tombstoned per r10; dealer→closed. Never left half-active | Saga orchestrator | No |
| Activate attempted with go-live checklist incomplete | Checklist evaluator finds unchecked items / non-done markers | **422** `{unmet:[step/checklist keys]}`; stays provisioning | Super Admin | Yes |
| Duplicate POST /platform/dealers (double-click) | Same Idempotency-Key, same body | In-flight → **409**; completed → stored **201** replay (NC-7) | API layer | No |
| Same key, different body | Idempotency store hash mismatch | **422** key_reuse_mismatch | API layer | No |
| Suspend a dealer mid-business-day | status active→suspended | Data-plane writes → **423** tenant suspended; reads still allowed; resume restores active (NC-3/NC-1) | Super Admin | Yes |
| Dealer-workspace user hits /platform/* | Session valid but lacks platform module | **403** RBAC denial (authenticated, not permitted — NC-1) | RBAC layer | No |
| Attempt to grant kill-switch via /admin/roles | governance capability requested in role payload | Rejected: kill-switch is platform-reserved governance, not grantable and not settings:admin (NC-13) | RBAC layer | No |
| Impersonating super-admin tries to activate a dealer | Session has impersonatedBy set, no elevation | HARD-BLOCK (NC-10); write refused, audit-logged; requires explicit elevation | Auth layer | No |
| Close requested before offboarding window elapsed | retention timer (r10) not expired | **422** {unmet:[retention_window]}; stays offboarding | Super Admin | Yes |

**📄 Documents / artifacts**

- **Provisioning saga ledger** — durable per-step marker rows + attempts/errors, source of truth for resume & compensation (audit-retained).
- **Go-live checklist** — stage_checklists-backed; evaluated deterministically to produce `{unmet:[]}` for activate.
- **Owner-admin invite email** — rendered via pdfkit/SMTP template, queued in `email_logs` outbox (see [r8](#r8) / [r6](#r6)).
- **Entitlement matrix snapshot** — per-dealer module + agent feature-flags (NC-9), server-authoritative.
- **Audit trail** — every create/activate/suspend/offboard/close/entitlement change and every saga step written to `audit_logs` with actor + `impersonatedBy` where applicable (see [r4](#r4), [r10](#r10)).
- **Note (NC-12 honesty scope):** "foolproof" here means application-logic + tenant/saga invariants only. NFRs (DR/backup, encryption-at-rest, HA/uptime, tracing, message broker) are PENDING-INFRA pre-GA blockers and are NOT claimed production-ready.
