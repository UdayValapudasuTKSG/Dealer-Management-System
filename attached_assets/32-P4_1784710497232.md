# Platform P4 — Super-Admin Ops & Cross-Tenant Governance Super Admin

**🚦 Flow (lowest level)**

- **Control-plane auth.** Super-admin signs into **Platform Console** (`/platform/*`). This is the **control-plane**: it carries NO `x-dealer-id` and is NOT subject to the dealer-scope resolver in **NC-14** — platform routes are gated by the caller's platform-role, not by `activeDealerId`. A missing session anywhere → **401**; a valid session lacking the platform capability → **403** (RBAC denial, see r4).
- **Tenant lifecycle.** Super-admin drives `dealers.status` exactly per r2: `provisioning → active → suspended → offboarding → closed`. Create returns **provisioning**; the go-live checklist flips to **active**. Provisioning runs as a **SAGA** (NC-11) with durable per-step markers + per-step compensation; `dealers.status` stays **provisioning** until every step completes, and NO DB transaction is ever held across a GCS/SMTP/LOS call.
- **Suspend / restore.** `active → suspended` blocks all **data-plane writes** for that tenant (dealer routes return **423** tenant suspended) while **reads remain allowed** (per NC-1). Restore `suspended → active` re-opens writes. Suspension is a control-plane act; the actual 423 is emitted by the data-plane middleware in the Dealer Workspace.
- **Impersonation (read-only by default).** Super-admin opens a time-boxed impersonation session into a dealer workspace. Default posture is **READ-ONLY**, **≤60 minutes**, **reason-logged**, and every request is stamped with `impersonatedBy` (NC-10). Under read-only impersonation the request pipeline strips write capability BEFORE RBAC evaluation, so every mutation is rejected regardless of the impersonated role's grants.
- **Write-elevation.** A write during impersonation requires an **explicit elevation** step (separate reason + short TTL). Even elevated, three classes are **HARD-BLOCKED** and can NEVER be performed under impersonation: **money-posting** (invoices/payments/receipts), **gate-resolution** (`gates/:id/resolve`), and **customer-sends** (outreach/WhatsApp/email to a customer). These blocks are enforced server-side and are not lifted by elevation.
- **Agent kill-switch (governance).** Super-admin toggles autonomous/HITL agents per dealer via the platform **governance** capability. This capability is **platform-reserved**: it is NOT grantable through `/admin/roles` and is NOT the same as `settings:admin` (NC-13). The switch drives `isAgentEnabled(semanticKey)` consumed by the data-plane.
- **Entitlements.** Super-admin manages per-dealer module/agent entitlements (feature flags). The request pipeline enforces an entitlement gate AFTER RBAC (NC-9, **INV-ENT-1**): a module/agent not entitled for a dealer → **404** (hidden, no existence leak), enforced server-side not merely in UI.
- **Audit read.** Every control-plane action (lifecycle transition, impersonation start/stop/elevation, kill-switch toggle, entitlement change) writes an immutable `audit_logs` row. Super-admin can query cross-tenant audit here (audit is the one legitimately cross-tenant read surface, see r4/r10).

**⚙️ Agents / automation**

- **Kill-switch fan-out.** Toggling `PATCH .../agents/:semanticKey` updates the per-dealer flag read by `isAgentEnabled(semanticKey)`. Valid keys are EXACTLY (r3, NC-6): `intake_dedup`, `call_sentiment`, `case_classifier`, `doc_prefill`, `outreach`, `test_drive_availability`, `pipeline_suggestions`, `sentiment_digest`, `persona_recommend`, `concierge`, `gra_extract`. Any other key → 422.
- **What the switch governs.** Autonomous LLM writers (A1 `intake_dedup`, A6 `call_sentiment`, A16 `case_classifier`) are the ONLY kill-switchable AI writers. Deterministic SYSTEM actions **A2 round_robin**, **A3 quote_tax**, **A11 vin_allocation** are plain code inside transactional flow — NOT "AI", NOT kill-switchable, and NOT toggleable here (r3). VIN allocation is deterministic on deal-commit and is NOT a gate (NC-4/NC-6).
- **Provisioning saga (NC-11).** Automated per-step markers: create dealer row → seed roles/role_permissions → provision GCS bucket → configure SMTP/Gmail intake → register LOS Demerara sandbox creds → seed dealer_taxes/lead_sources. Each step has a compensation; failure mid-saga leaves `dealers.status=provisioning` and surfaces the failed step to the console. No external call runs inside a DB transaction.
- **Impersonation guard automation.** Middleware auto-expires sessions at `expiresAt`, auto-demotes `write_elevated → read_only` when the elevation TTL lapses, and unconditionally rejects the three hard-blocked classes (money-post / gate-resolve / customer-send) before handler dispatch.
- **Entitlement gate.** After RBAC, the pipeline checks the per-dealer entitlement set (INV-ENT-1); non-entitled module/agent → 404 server-side. This is automation shared with every data-plane route, configured from this section.

**🧠 AI for the persona**

- **No autonomous AI on the control-plane.** Platform Console has NO agent that writes tenant data. The super-admin's AI surface is advisory/read-only only.
- **Governance digest (advisory).** A read-only rollup of `agent_runs` + `audit_logs` highlights agents with high error/kill rates across tenants so the admin can decide to flip a kill-switch. It recommends; the human toggles.
- **Impersonation-safety reminder.** When an admin opens an impersonation session, the UI states the read-only default and the hard-blocked classes; any AI-assisted "explain this tenant" answer is generated from data the admin is already permitted to read and never triggers a write or a customer-send (concierge is nav-only and dealer-scoped, r3).
- **Honesty scope (NC-12).** AI assistance here is bounded by application-logic + tenant/money/AI invariants; it makes NO claim about DR/backup, encryption-at-rest, HA/uptime, tracing, or message-broker readiness — those are PENDING-INFRA pre-GA blockers tracked in V4, distinct from r9 built-app defects.

**🔑 Key fields · validations · SLA**

- **Status codes (NC-1) on platform routes:** 401 no/invalid session; 403 authenticated-but-not-permitted (platform RBAC denial); 404 dealer id not found within permitted scope / non-entitled target (no existence leak); 409 idempotency in-flight/duplicate or write conflict; 422 validation / unmet checklist `{unmet:[]}` / `key_reuse_mismatch`; 429 rate-limited (+Retry-After). Note: 423 is emitted by the **data-plane** for a suspended tenant, not by these control-plane routes.
- **Idempotency (NC-7):** every mutation above requires `Idempotency-Key`. Completed replay → stored response; in-flight dup → 409; same key + different body → 422 `key_reuse_mismatch`.
- **Impersonation invariants (NC-10):** `mode` ∈ {`read_only`(default), `write_elevated`}; `ttlMinutes ≤ 60`; `reason` required (non-empty); `impersonatedBy` stamped on every request & audit row. HARD-BLOCKED even when elevated: money-posting, gate-resolution, customer-sends.
- **Governance capability (NC-13):** `platform:governance` is a platform-reserved capability, disjoint from `settings:admin` and NOT expressible in `role_permissions.module` vocabulary (r5) — so it cannot be granted via `/admin/roles`.
- **Dealer fields:** `region` ∈ {CAM, GT}; `usdExchangeRate` (~209) drives GYD display = USD-scale × rate; `status` per r2 lifecycle only.
- **SLA:** lifecycle transitions synchronous ≤2s; provisioning saga is async with durable markers (no fixed wall-clock — go-live gated on completion); impersonation session auto-terminates at TTL; kill-switch flag propagation to data-plane ≤5s (read at request time via `isAgentEnabled`).

**🔀 Edge-of-edge cases → handling**

| Scenario | Detection | Handling | Owner | HITL? |
| --- | --- | --- | --- | --- |
| Mutation attempted under read-only impersonation | Pipeline sees `mode=read_only` + write verb | Reject **403** before RBAC; audit the blocked attempt with `impersonatedBy` | Impersonation middleware | No (auto) |
| Elevated admin tries money-post / gate-resolve / customer-send | Route matches hard-blocked class list | Reject **422** `impersonation_write_forbidden` regardless of elevation scope; audited | Impersonation middleware | No (hard-block) |
| Impersonation TTL > 60m requested | Validation on create/elevate | **422**; session capped, never issued beyond 60m | Platform API | No |
| Session outlives `expiresAt` | Middleware clock check | Auto-end; next request → **401** on the impersonation context (super-admin's own session intact) | Middleware | No (auto) |
| Attempt to grant `platform:governance` or kill-switch via `/admin/roles` | Module vocabulary excludes the capability (r5) | Not selectable; API rejects unknown module → **422**; capability stays platform-reserved (NC-13) | RBAC editor + API | No |
| Kill-switch toggle for a deterministic key (round_robin/quote_tax/vin_allocation) | Key not in semanticKey allow-list | **422** unknown key — these are SYSTEM code, not kill-switchable (NC-6) | Platform API | No |
| Suspend during in-flight tenant write | Data-plane re-reads `dealers.status` at request time | In-flight completes or fails per its own txn; NEW writes → **423**; reads stay allowed | Data-plane middleware | No |
| Provisioning saga step fails (GCS/SMTP/LOS) | Durable step marker not set | Run per-step compensation; keep `status=provisioning`; surface failed step; retryable (NC-11) | Provisioning saga | Admin retry |
| Cross-tenant read attempted on a data-plane route via platform session | No `x-dealer-id` / not caller membership | Data-plane still enforces scope: foreign row → **404** (no leak); header missing on mutation → **400** `dealer_required` (NC-14) | Data-plane resolver | No |
| Non-entitled module toggled off while a user is mid-session | Entitlement gate after RBAC (INV-ENT-1) | Subsequent calls to that module → **404** hidden, server-side | Entitlement gate | No |
| Duplicate suspend click | Same `Idempotency-Key` | Replay → stored response; in-flight → **409**; different body same key → **422** `key_reuse_mismatch` | Platform API | No |

**📄 Documents / artifacts**

- **Impersonation audit record** — `audit_logs` rows for start/elevate/end, carrying `impersonatedBy`, `reason`, `mode`, `scope`, `expiresAt`, and every blocked-write attempt (r10 data-subject / accountability trail).
- **Go-live checklist artifact** — the `stage_checklists`-style provisioning checklist whose completion drives `provisioning → active`; unmet items returned as `{unmet:[]}`.
- **Kill-switch change log** — per-dealer agent-governance history (who toggled which `semanticKey`, reason, timestamp) in `audit_logs`.
- **Entitlement matrix export** — per-dealer module/agent entitlement state (INV-ENT-1) for compliance review.
- **Cross-tenant audit export** — filtered `audit_logs` extract; async accepted (**202**) for large exports, delivered via the outbox (r6 notifications).
- No PDF templates originate here; PDFs (invoice, delivery) are data-plane artifacts (r8). Corrected-design target tables (`test_drives`, `service_cases`, `reviews`) are documented in X1 as corrected-design additions (NC-8, r9), not created from this console.
