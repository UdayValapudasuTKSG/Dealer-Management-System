# Layer 7 — Pre-Delivery (Ready for Delivery) Delivery Advisor

**🚦 Flow (step-by-step, lowest level)**

- **1. Auto-provision on commit.** When Layer 6 fires `PATCH /deals/:id` with `stage=committed`, the server VIN-locks the vehicle (agent **A11**), sets `vehicles.status='booked'`, and **auto-creates the delivery** row with the 9-step `steps` jsonb all in `pending`. Delivery inherits `dealId`, `customerId`, `vehicleId`, `activeDealerId`, `divisionId`.
- **2. Ownership handoff.** Delivery lands in the `GET /delivery-advisors` pool; a Delivery Advisor is picked (or round-robin via `dealer_users.lastLeadAssignedAt`) and set on the delivery. Timeline event written (per-entity, `isAgent=false`).
- **3. Step 1 sales_order.** Advisor opens the single Workflow console; primary CTA is **"Advance to PDI Checklist"** (one CTA only — the old "Run Review" readiness view is merged in as an inline **Readiness check** panel). `POST /deliveries/:id/advance` validates prior-step completeness; returns `422 {unmet:[]}` if the sales order isn't confirmed.
- **4. Step 2 pdi_checklist.** Advisor works the PDI via `PATCH /deliveries/:id/pdi`, ticking each `pdiItems[]` (exterior, interior, fluids, tyre pressure, road-test, accessories present). Every item must be `pass` or explicitly `waived+reason` before advance.
- **5. Step 3 registration.** Advisor records the 3rd-party GRA/registration submission status (`pending|submitted|issued`) and the plate `registration` (validated `^[A-Z]{3}[0-9]{1,4}$`). **GRA duty/VAT is server-computed deterministically** from `dealer_taxes` at invoice step — never invented by AI; a `gates.type='gra_filing'` gate confirms before any GRA submit.
- **6. Step 4 insurance.** Advisor attaches the insurance cover note (`customer_documents` / polymorphic `documents`), which may be AI pre-filled (agent **A5**, `extractionStatus:'proposed'`) then HITL-confirmed via `POST /documents/extraction/review`.
- **7. Step 5 invoice.** Advance triggers **auto-invoice**: server recomputes OTD from `deals.otdPrice` + `dealer_taxes` (VAT 0%/14% by model, import duty, EV exclusions) in GYD (USD-scale × `dealer.usdExchangeRate`), issues `invoices` (`status='issued'`), and pdfkit renders the delivery invoice.
- **8. Readiness gate.** Inline Readiness check aggregates: PDI 100% pass, registration issued, insurance attached, invoice issued, deposit/balance status. Handover cannot advance to `appointment`/`delivery` until all green — `422 {unmet:[]}` otherwise. This is the **Layer-7 exit**; Layers 8+ (appointment→signature→feedback) follow.
- **9. Handover pack pre-fill.** Handover checklist / delivery note PDF fields (owner name, VIN, engine no., plate, accessories) are pre-filled from grounded rows; advisor reviews before the appointment step.

**⚙️ Agents in play**

- **A11 VIN allocation** → trigger: deal commit in Layer 6 → inputs: `deals.vehicleId`, `vehicles(status,holdUntil)` scoped to dealer → output: VIN-lock (`vehicles.status='booked'`, `holdReason='deal_committed'`) + auto-created `deliveries` row → HITL: **no** (deterministic); audited via `recordAgentRun`, kill-switchable via `agents.status`.
- **A5 Document pre-fill (vision)** → trigger: insurance cover note / registration doc uploaded → inputs: uploaded `documents.extraction` (untrusted text wrapped with `guardUntrusted`) → output: `{fields}` restricted to allowlist `PREFILL_FIELDS`, `extractionStatus:'proposed'`, `confidence` → HITL: **yes** — advisor confirms via `/documents/extraction/review`; below `MIN_AGENT_CONFIDENCE` routes to human, no auto-fill.
- **A3 Quote/Code (tax engine)** → trigger: invoice step advance → inputs: `deals.otdPrice`, `dealer_taxes` rows (VAT/duty/excise, `excludeEv`, threshold), `dealer.usdExchangeRate` → output: deterministic `taxLines[]` + pdfkit invoice PDF → HITL: **no** (pure compute, no LLM); GRA figures never LLM-generated.
- **GRA vision extract** → trigger: `POST /gra/extract` on registration/import doc → inputs: doc image, dealer-scoped → output: **legible fields ONLY** (never invents TIN/VIN/CIF/duty); **server** computes tax; `gates.type='gra_filing'` → HITL: **yes**, manager resolves gate before `/gra/filings`.

**🧠 AI for the persona**

- Readiness check panel surfaces a plain-language "**3 items blocking handover**" summary derived from the `unmet[]` array — deterministic, not generative.
- Pre-filled handover/insurance fields shown as **proposed (yellow)** chips the advisor taps to confirm; extraction confidence displayed; sub-floor confidence auto-hidden and flagged "manual entry required".
- GRA extract shows only fields the vision model could **actually read** off the document, each with a "verify against source" prompt; computed duty/VAT shown separately with the `dealer_taxes` rule that produced it.
- No auto-send: any customer-facing "your car is ready" outreach is drafted by **A7** (`agent-brief`) and requires human Approve & Send.

**🔑 Key fields · validations · SLA**

- **Fields:** `deliveries.steps` (jsonb 9-step, this layer covers sales_order→invoice), `pdiItems[]`, `registration`, `registrationStatus`, `signatureData`(later), `serviceAdvisorUserId`, `invoiceId`.
- **Validations:** plate `^[A-Z]{3}[0-9]{1,4}$`; VIN & `engineNumber` = 17 chars (read-only, from vehicle); PDI item `waived` requires `waiveReason`; advance blocked unless prior step complete (`422 unmet[]`).
- **Tax/config:** `dealer_taxes` (VAT percent 0|14 by model, import duty, excise, `threshold`, `excludeEv`) computed server-side; money USD-scale → GYD × `dealer.usdExchangeRate`(~209); dates `America/Guyana` GMT-4.
- **SLA:** PDI complete within 48h of handoff; registration follow-up reminder at 72h; invoice must be `issued` before appointment scheduling; `stageEnteredAt`/step timestamps drive aging.
- **Scoping:** every query filtered by `activeDealerId(res)` + `x-dealer-id`; object-storage cover-note fetch enforces per-object ACL.

**🔀 Edge-of-edge cases → handling**

| Scenario | Detection | Handling | Owner | HITL? |
| --- | --- | --- | --- | --- |
| PDI item failed (e.g. paint defect) | `pdiItems[].status='fail'` | Block advance; create rectification `task`; vehicle returns to prep; re-PDI required | Delivery Advisor | Yes |
| PDI waived without reason | `status='waived'` & empty `waiveReason` | `400`; force reason entry | Server | Yes |
| Registration stuck at 3rd-party (GRA delay) | `registrationStatus='submitted'` > 72h | Reminder + timeline flag; advisor may proceed to insurance but handover gate stays red | Delivery Advisor | Yes |
| AI invents TIN/VIN/CIF on GRA doc | Field not in legible extract / allowlist | Reject; blank field; server-compute duty; `gra_filing` gate must confirm | Server + Manager | Yes |
| Extraction confidence below floor | `confidence < MIN_AGENT_CONFIDENCE` | No auto-fill; route to manual entry; audit run | Agent framework | Yes |
| Invoice recompute mismatch (exchange rate changed) | OTD ≠ deal `otdPrice` at issue | Recompute from current `dealer_taxes`+rate; log delta; below-floor discount re-check | Server | No |
| Vehicle soft-lock (`holdUntil`) expired mid-delivery | Lazy-expiry check on advance | Re-assert VIN-lock (deal committed overrides); refuse release | Server (A11) | No |
| Concurrent advance (two advisors) | Duplicate `idempotencyKey` / step version | Idempotent replay returns same result; second writer `409` | Server | No |
| Cross-tenant delivery access | `activeDealerId` ≠ row dealer | `404` (not 403, no existence leak) | Server | No |
| Untrusted insurance/reg doc text (injection) | Uploaded doc / OCR text | `guardUntrusted` wrap before any AI/prompt use | Server | No |
| Insurance cover note missing at invoice step | No `insuranceDocId` | `422 {unmet:["insurance_missing"]}` | Server | Yes |
| Object-storage cover note ACL breach | Presigned URL for other dealer's object | Deny per-object ACL check; `403` | Server | No |
| Balance unpaid but advisor tries handover | `invoices.status='partially_paid'` | Warn; handover gate red until `paid` (config) | Delivery Advisor | Yes |
| Agent kill-switch active | `agents.status='paused'` | Skip A5/GRA extract; require full manual entry; note in audit | Server | Yes |
| Deal un-commits / cancels after delivery created | Deal stage regress | Void draft invoice, release VIN-lock, cancel delivery, notify advisor | Server + Advisor | Yes |
| EV incorrectly taxed duty | `dealer_taxes.excludeEv` not applied | Server skips duty line for EV models; recompute | Server | No |

**📄 Documents & PDF format**

- **Delivery Invoice PDF** — generator `pdfkit` (delivery invoice module) via `GET /deliveries/:id/invoice.pdf`; channel: download + email outbox (`email_logs`, retry/backoff/dedupe) / WhatsApp on customer opt-in. **Layout:** Header (dealer logo, dealer name + division CAM/GT, TIN, `invoiceNumber`, issue date America/Guyana). Bill-To (customer/business, address). Vehicle block (make/model/trim/year, **VIN 17**, engine no. 17, `registration` plate, colour, accessories). Line-item table columns: `Description | Qty | Unit (GYD) | VAT% | Amount (GYD)` — vehicle price, accessories, then **tax lines from `dealer_taxes`** (VAT 0/14%, import duty, excise). Totals block: subtotal, total tax, **OTD total GYD**, deposit paid, balance due. Footer: server-computed note "Taxes computed per GRA schedule", payment terms, dealer contact.
- **PDI / Handover Checklist** — generated from `pdiItems[]`; sections: Exterior, Interior, Mechanical/Fluids, Road-test, Accessories, Documents. Columns: `Item | Pass/Fail/Waived | Notes`; footer: advisor name, date, customer signature block (populated at signature step). Delivered in handover pack.
- **Registration / GRA filing doc** — consumed via `POST /gra/extract` (vision, legible fields only); produced filing summary shows server-computed duty/VAT with source `dealer_taxes` rule and `gates.type='gra_filing'` evidence trail; no AI-invented figures.
- **Insurance cover note** — consumed (uploaded to `documents`, polymorphic), A5 pre-fills allowlisted fields `extractionStatus:'proposed'`, HITL-confirmed; stored under dealer-scoped object ACL.
