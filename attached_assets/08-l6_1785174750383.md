# Layer 6 — Payment (Payment in Progress) Finance / Sales Advisor

**🚦 Flow (step-by-step, lowest level)**

- **1. Deal snapshot & below-floor gate.** Advisor opens the `deal` (stage `desking`) and enters negotiated `vehiclePrice`, `discount`, `tradeInValue`. On `PATCH /deals/:id` the server recomputes `otdPrice` via the **dealer_taxes** engine. If `discount > 5%` of `vehiclePrice`, server refuses to advance and opens a `gates` row `type=below_floor_price` (evidence = price math snapshot). Advance is blocked until a manager runs `POST /gates/:id/resolve` (this is an **Approval**, not a Readiness check — see disambiguation). Every query is scoped by `activeDealerId(res)` + `x-dealer-id`; division CAM/GT carried from the lead.
- **2. Financing branch (optional).** If not cash, advisor creates `finance_applications` (`amount`, `downPayment`, `termMonths`, `apr`, `bankId`). `POST /finance-applications/:id/submit` pushes to LOS via `losConnector` (**live** = Demerara Bank REST, else **sandbox** DTI underwriting); `los_submissions.mode` records which. Status walks `pending→submitted→under_review→approved|declined→disbursed`. A `declined` result opens `gates` `type=credit_decline` for human handling. `lead.financingQualified` flips on `approved`.
- **3. Reservation invoice (dual-invoice #1).** When a `booking` (reservation) exists, server issues the first `invoices` row for the `bookingAmount`/reservation fee (status `issued`). `lead.reservationFeePaid` tracks its settlement.
- **4. Take payment (idempotent).** Advisor records money via `POST /payments` with an `Idempotency-Key` header (row in `idempotency_keys`). Method ∈ `cash|card|bank_transfer|cheque|mobile_money|financing` — **no gateway**, this is an internal ledger only. Server recomputes the target invoice's paid total, transitions `issued→partially_paid→paid`, and emits a `receipts` row + timeline_event.
- **4b. Commit precondition (`desking→committed`).** `PATCH /deals/:id → committed` is REFUSED (`422`) unless a reservation **deposit is recorded** (a `booking` with `bookingAmount>0` & `reservationFeePaid=true`) **OR** a manager-approved **trusted-bypass waiver** gate is resolved — in addition to the `below_floor_price` (if discounted) and `capital_order` (fleet/capital) gates. A deal desked directly (no prior reservation) has no deposit and cannot commit until one of these is satisfied. The UI MUST surface **"Record deposit"** and **"Apply trusted bypass (manager)"** actions instead of a dead-end error.
- **5. Final invoice (dual-invoice #2).** On deal `commit`, VIN-lock fires (A11) and the server auto-generates the final `invoices` for `otdPrice` minus reservation fee minus `tradeInValue` minus `downPayment`/financed portion. Tax lines mirror `quotes.taxLines[]` recomputed at commit time.
- **6. Balance & reconcile.** `GET /outstanding-balances` surfaces net due per customer/deal. When invoice hits `paid` and (cash) or `disbursed` (financing), `deal.depositPaid`/settlement satisfied — this feeds the Layer-7 delivery checklist gate (`invoice` step). Over/under/bounced handled per edge table.
- **7. Refund / release path.** Any refund (cancelled booking, void invoice) opens `gates` `type=refund_release`; ledger reversal only after resolve. Voids never delete — invoice moves to `void` and a reversing receipt is written.

**⚙️ Agents in play**

- **A3 Quote/Code (deterministic tax engine)** → trigger: `PATCH /deals/:id` price change & invoice creation → inputs: `deals.vehiclePrice/discount/tradeInValue`, `dealer_taxes` (VAT 0%/14% by model, import duty, excise; `threshold`, `excludeEv`), `dealer.usdExchangeRate` → output: `{taxLines[], otdPrice, total}` written to `quotes`/`invoices`. **Not an LLM** — pure server math. HITL: no (but below-floor result routes to a human gate).
- **A11 VIN allocation** → trigger: deal `commit` → inputs: `vehicles` row for `interestedVehicleId`, current `status` → output: VIN-lock, `vehicles.status→booked`, final invoice seeded. HITL: no; concurrency guarded (edge table).
- **LOS connector (Demerara live / sandbox DTI)** → trigger: `/submit`+`/sync` → inputs: `finance_applications` + `banks`; **declared, audited via recordAgentRun, kill-switchable** (`agents.status`). Output: underwriting decision. HITL: **yes** — a `declined` raises `gates type=credit_decline`; server never auto-approves financing.
- **A6 Call sentiment (fire-and-forget, autonomous-write)** → only if advisor logs a payment-negotiation call note → wrapped in `guardUntrusted`, `isAgentEnabled` checked, `recordAgentRun` written. Below `MIN_AGENT_CONFIDENCE` → no write, routed to human. HITL: implicit (advisor edits).
- **No AI touches money.** Tax, APR selection floor, and invoice totals are deterministic. AI never invents amounts, TIN, CIF, or duty (GRA correction) — any GRA/tax doc extraction is Layer-elsewhere and server-computed.

**🧠 AI for the persona**

- **Agent brief on the deal** (`GET /leads/:id/agent-brief`) surfaces `{headline, riskLevel, actions[], draftMessage}` — e.g. "Balance GYD 1,463,000 outstanding 6 days; draft payment reminder." Advisor must **Approve & Send** via `/outreach` or `/whatsapp` — never auto-sent.
- **Pipeline suggestions** (`GET /pipeline/suggestions`) flags deals stalled at partial-payment so finance can nudge, grounded on real `invoices.status=partially_paid` rows only.
- Below-floor context: the `below_floor_price` gate card shows the deterministic margin math for the manager — AI is advisory only, the number is server-computed.
- All inbound customer text used in drafts (WhatsApp/email replies about payment) is wrapped with `guardUntrusted` before reaching the model.

**🔑 Key fields · validations · SLA**

- **Money scale:** all amounts stored `USD`-scale; GYD display = `amount × dealer.usdExchangeRate` (~209). Round GYD to whole; never store the GYD figure.
- **Below-floor:** `discount / vehiclePrice > 0.05` → mandatory `gates type=below_floor_price`; advance/commit returns `422` until resolved.
- **Idempotency:** every `POST /payments` requires `Idempotency-Key`; replay returns the original `200` result, never double-posts the ledger.
- **dealer_taxes engine:** per line — `VAT (0% EV / 14% std)`, `import duty`, `excise`; `percent|fixed`, `threshold`, `excludeEv`. Recomputed at deal edit and again at commit (values may drift).
- **Invoice status machine:** `issued→partially_paid→paid` (or `void`). `void` is terminal + writes a reversing receipt.
- **Finance validations:** `termMonths > 0`, `downPayment ≤ amount`, `apr` within bank band; `bankId` must be dealer-scoped active.
- **Dual invoice:** reservation invoice (bookingAmount) + final invoice (otdPrice − reservation − tradeIn − down/financed). Sum of applied payments across both = total settlement.
- **SLA:** partial-payment reminder at +72h; booking soft-lock (`holdUntil`/`expiresAt`) lazy-expiry on `/bookings/:id/remind`; LOS `/sync` poll cadence until decision, credit gate SLA 24h.
- **Currency stamping:** receipts & invoices persist `currency:"USD"` and snapshot `exchangeRate` used, so historical GYD display is reproducible even after rate change.

**🔀 Edge-of-edge cases → handling**

| Scenario | Detection | Handling | Owner | HITL? |
| --- | --- | --- | --- | --- |
| Overpayment (amount > balance) | server: `appliedAmount + amount > total` | `422 {error:"overpayment", excess}`; advisor either reduces or records excess as credit on `customers.lifetimeValue` ledger for next invoice | Finance | Yes |
| Underpayment / partial | paid < total | invoice → `partially_paid`; `/outstanding-balances` shows remainder; +72h reminder task | Finance | No (auto), reminder approved by human |
| Bounced cheque / reversed transfer | manual mark or bank feed reversal | write reversing `payments` (negative) + reversing receipt; invoice recomputes back to `partially_paid`/`issued`; notify advisor | Finance | Yes |
| Duplicate submit (double-click) | same `Idempotency-Key` | return cached `200`; no second ledger row | System | No |
| Discount edited above floor after gate approved | commit recompute vs approved evidence snapshot | stale approval invalidated; new `below_floor_price` gate required | Manager | Yes |
| Exchange rate changes mid-deal | invoice snapshot rate ≠ current | historical docs use stored rate; new invoices use current; balance display flagged with rate note | System | No |
| Concurrent VIN allocation (two deals, one vehicle) | A11 row-lock on `vehicles.status` | first commit wins → `booked`; second gets `409 vehicle_unavailable`, advisor re-selects | System / Advisor | Yes (re-select) |
| Booking soft-lock expired before final payment | lazy-expiry on `/bookings/:id/remind`, `expiresAt<now` | booking → `expired`, vehicle released; reservation fee refund gate opens | Finance | Yes (refund gate) |
| LOS unreachable (live Demerara down) | `502` on submit/sync | retry w/ backoff; offer fallback to sandbox mode only with manager note; app stays `submitted` | Finance / System | Yes |
| Finance declined | `/sync` → declined | `gates type=credit_decline`; advisor switches to cash or alt bank; deal cannot commit financed | Manager + Finance | Yes |
| Cross-tenant payment attempt | `x-dealer-id` ≠ invoice.dealerId | `404` (not 403 — no existence leak); audit-log the attempt (dealer-scoped) | System | No |
| Refund on already-delivered asset | `assets.deliveredAt` set | hard block; requires `refund_release` gate + manager + ops sign-off | Manager | Yes |
| WhatsApp payment reminder undelivered / opt-out | outbox failed status / opt-out flag in `whatsapp_conversations` | backoff+dedupeKey; after N fails fall back to email; suppress if opted-out; task to call | Finance / System | Partial |
| Void invoice with payment applied | void request where `paid>0` | block direct void; require full refund/reversal first, then `void` + reversing receipt | Finance | Yes |
| Trade-in value exceeds vehicle price | `tradeInValue > vehiclePrice` | `422` validation; negative OTD not allowed; excess handled as separate credit | Finance | Yes |
| Mobile-money reference collision | duplicate `reference` within dealer | warn; require confirm; store both with distinct receipts | Finance | Yes |
| EV wrongly taxed VAT/duty | `dealer_taxes.excludeEv` vs vehicle EV flag | engine suppresses excluded lines; if mismatch, recompute + reissue invoice | System | No |

**📄 Documents & PDF format**

- **Reservation Invoice (PDF, pdfkit)** — delivery: email outbox + WhatsApp link. Layout: **Header** dealer logo + name (CAM Motors / GT Automotive), division, `invoiceNumber`, issue date (America/Guyana), status badge. **Party block** customer + contact. **Line items** columns [Description | Qty | Unit (USD) | VAT | Amount (USD)] + GYD equivalent column at stored rate. **Totals** subtotal, tax lines (VAT/duty/excise), reservation fee due. **Footer** "USD ledger — GYD @ {rate}", terms, TIN placeholder left blank (never AI-filled).
- **Final Sales Invoice (PDF, pdfkit)** — auto-generated on commit. Same skeleton; line items show `vehiclePrice`, `discount` (as negative line, gate-approved), `tradeInValue` (negative), tax lines from `dealer_taxes`, then `otdPrice`. Credits row for reservation fee + downPayment + financed amount → **net balance due**. VIN/registration printed only from the locked `vehicles` row. Feeds Layer-7 delivery `invoice` step.
- **Receipt (PDF, pdfkit)** — per `payments` row. Header `receiptNumber`, linked `invoiceNumber`. Body: amount (USD + GYD), `method`, `reference`, `receivedAt`, running balance after this payment. Reversing receipts render amount in parentheses (negative) with reason. Delivery: email/WhatsApp outbox, downloadable via `/receipts/:id`.
- **Outstanding-balance statement** — from `GET /outstanding-balances`, on-screen + optional PDF: per-deal otdPrice, paid, financed, balance, currency + GYD display; used for the +72h reminder draft (human-approved before send).
