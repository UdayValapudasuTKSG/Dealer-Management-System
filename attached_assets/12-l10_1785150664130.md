# Layer 10 — Service handoff & Intro Service Advisor

**🚦 Flow (step-by-step, lowest level)**

- **Trigger — Asset born on delivery:** when `POST /deliveries/:id/advance` reaches the final 11th step (`feedback`) it fires the delivered-side side-effects: auto-invoice, `assets` row created (`accountId`, `vehicleId`, `dealId`, `deliveryId`, `deliveredAt`), and **A-ServiceAssign** stamps `assets.serviceAdvisorUserId` via deterministic round-robin over `dealer_users` filtered by role=Service Advisor + matching `divisionId` (CAM/GT). Every write dealer-scoped to `activeDealerId(res)`.
- **Task materialization:** a `tasks` row "Intro call — {customer}" is created with `dueAt = deliveredAt + 5 business days` (America/Guyana GMT-4, dealer working-days calendar), `assigneeUserId = serviceAdvisorUserId`. A `timeline_events` entry (per-asset, `isAgent=false`) records the handoff.
- **Advisor opens the Asset/Case console:** `GET /customers/:id/assets` then `GET /customers/:id/overview` to see `lifetimeValue`, `loyaltyTier`, primary contact, prior notes. Concierge grounding here is dealer-scoped.
- **Coverage confirmation:** advisor pulls `GET /coverage?vehicleId=…` to read the warranty / AMC `coverage_plans` attached to the delivered vehicle (start = `deliveredAt`, term, mileage cap). If none attached, advisor creates one via `POST /coverage` (no auto-create — capital/commitment stays human).
- **Intro call (SLA ≤ 5 business days):** advisor places call through `POST /leads/:id/calls`-equivalent on the customer/asset (Twilio browser or Stub adapter). Call note logged to `call_logs` (`provider`, `sentiment` null until scored). Inbound/typed notes wrapped with **`guardUntrusted`** before any AI touches them.
- **Sentiment (fire-and-forget):** A6 Call-sentiment auto-runs on the saved call note; advisor may re-run manually via `POST …/calls/:cid/suggest-sentiment`. If A6 confidence < `MIN_AGENT_CONFIDENCE` the label is withheld and routed to the human (shown as "needs review", never written as fact).
- **Set service cadence:** advisor confirms/edits the AI-suggested next-service interval, then persists it — creating the first future `service_orders` (type=scheduled, `status`=open, `scheduledDate`) + a reminder cadence. This is the first-class **Case** object, not a lead field.
- **Unreachable path:** if no answer, advisor marks call outcome=unreachable → task auto-reschedules with backoff (attempt 1 → +1d, 2 → +2d, 3 → +3d), max 3 attempts inside the 5-day window; on exhaustion a WhatsApp/email intro goes out via the `email_logs` outbox and the task escalates to the reporting manager (`dealer_users.reportingManagerUserId`).
- **Close handoff:** once contacted + cadence set + coverage confirmed, advisor marks the intro task done; `timeline_events` logs completion and the asset enters normal service lifecycle.

**⚙️ Agents in play**

- **A-ServiceAssign (deterministic, not LLM):** trigger = delivery final-step Asset creation → inputs: `dealer_users` (role=Service Advisor, matching `assets.vehicleId→division`), least-recently-assigned clock → output: sets `assets.serviceAdvisorUserId` + creates intro `tasks` row. HITL: no (deterministic, audited to `timeline_events`). Kill-switch via `agents` row not required (no LLM) but reversible by manager reassignment.
- **A6 Call-sentiment (claude-sonnet-4-6, autonomous-write, declared + kill-switchable):** trigger = save of intro call note (fire-and-forget) + manual `/suggest-sentiment` → inputs: single `call_logs.note` only, PII-minimized, **`guardUntrusted`**-wrapped → output `{sentiment,confidence}` written to `call_logs.sentiment` ONLY if `confidence ≥ MIN_AGENT_CONFIDENCE`; else routed to human as "needs review". Every run rows into `agent_runs` (`runType,inputSummary,outputSummary,confidence,latency`); paused via `agents.status=paused`. HITL: soft — advisor can override the label.
- **A15 Pipeline / cadence suggestion (assistive):** trigger = advisor opens cadence panel → inputs: `coverage_plans` term, vehicle make/model service schedule, `assets.deliveredAt`, odometer → output: proposed next `scheduledDate` + interval (draft only, never writes `service_orders` itself). HITL: yes — advisor confirms before `POST /service-orders`.
- **A7 Outreach composer (draft-only, never auto-send):** trigger = unreachable path → `GET /leads/:id/agent-brief`-style brief returns `{headline,riskLevel,actions[],draftMessage}` for the intro WhatsApp/email → advisor "Approve & Send" via `/whatsapp` or `/emails/send`. HITL: yes — hard gate, no autonomous send.

**🧠 AI for the persona**

- "Suggested first-service cadence: **6 months / 5,000 km** for this Toyota trim — confirm to schedule." (A15 draft; advisor edits date, then persists as a Case).
- Call-outcome sentiment chip on the intro call note: **Positive / Neutral / Negative** — shown only above confidence floor; otherwise "AI unsure — review".
- Drafted intro message for the unreachable customer (A7): editable text, WhatsApp-first if opted-in, with coverage highlights — advisor approves before send.
- Coverage expiry watch: "Warranty ends {endsAt}; AMC renewal opportunity" surfaced from `coverage_plans`, dealer-scoped.
- Concierge (SSE `/anthropic`, nav-only) can answer "what's covered on this asset?" using dealer-scoped grounding — read-only, no mutations.

**🔑 Key fields · validations · SLA**

- **Assignment:** `assets.serviceAdvisorUserId` must resolve to an active `dealer_users` with role Service Advisor + same `divisionId` as the vehicle; else fallback to manager queue.
- **Intro SLA:** intro contact due `deliveredAt + 5 business days` (America/Guyana GMT-4, dealer calendar excludes weekends/holidays). Breach = task turns red + escalation to `reportingManagerUserId`.
- **Retry policy (unreachable):** max 3 call attempts, backoff +1d/+2d/+3d, all inside the 5-day window; on exhaustion → outbox message + escalation.
- **Coverage:** `coverage_plans.startsAt = deliveredAt`; `endsAt > startsAt`; no overlapping active plan per `vehicleId`; `type ∈ {warranty, AMC}`; money USD-scale, GYD display = ×`dealer.usdExchangeRate`.
- **Service order:** `scheduledDate > now`; `odometer` integer ≥ 0; `type=scheduled` for cadence; VIN/registration on vehicle already locked from delivery.
- **Confidence:** A6/A15 outputs gated by `MIN_AGENT_CONFIDENCE` — below floor never written, routed to human.
- **Guarding:** every call note, inbound WhatsApp/email reply, and customer-typed text passes `guardUntrusted` before AI; PII-minimized before any model call.
- **Dealer-scope:** all reads/writes filtered by `activeDealerId(res)` incl. concierge grounding, object-storage ACL, and audit-logs.
- **Config touched:** dealer working-days calendar; `dealer_taxes` only for coverage pricing tax lines; outbox retry/backoff/dedupeKey for reminders.

**🔀 Edge-of-edge cases → handling**

| Scenario | Detection | Handling | Owner | HITL? |
| --- | --- | --- | --- | --- |
| No active Service Advisor in vehicle's division | A-ServiceAssign finds empty round-robin pool | `serviceAdvisorUserId=null`; task lands in manager unassigned queue with alert | Service Manager | Yes — manual assign |
| Assigned advisor deactivated / on leave before intro | Task assignee `dealer_users.active=false` on load | Auto-reassign to next round-robin peer; timeline logs reassignment | A-ServiceAssign / Manager | No (auto), manager can override |
| Customer unreachable after 3 attempts | 3× `call_logs.outcome=unreachable` within window | A7 drafts intro WhatsApp/email → advisor approves → outbox send; task escalates to manager | Service Advisor | Yes — approve send |
| WhatsApp opt-out / 24h window closed | Meta/Twilio error `131047` / no session | Fall back to template message or email; if opt-out flag set, suppress WhatsApp entirely, use email only | Outbox worker | No |
| Outbox message failed delivery (bounce/hard fail) | `email_logs.status=failed` after retry/backoff exhausted | Surface to advisor as failed; try alternate channel; keep task open past SLA with reason | Service Advisor | Yes — pick channel |
| Duplicate reminder fired | Same `dedupeKey` in email_logs | Outbox dedupe drops the second; single send guaranteed | Outbox worker | No |
| Intro SLA breached (past 5 business days) | Task `dueAt < now`, status not done | Task flagged red; escalate to `reportingManagerUserId`; breach recorded on timeline | Service Manager | Yes — follow-up |
| Coverage plan overlaps existing active plan | `POST /coverage` overlap check | `422 {unmet:['overlapping_active_plan']}`; advisor edits dates or voids old plan | Service Advisor | Yes |
| Vehicle delivered with NO coverage attached | `GET /coverage` returns empty | Prompt advisor to create plan during intro; not auto-created (capital/commitment) | Service Advisor | Yes |
| A6 sentiment low confidence | `confidence < MIN_AGENT_CONFIDENCE` | Label withheld; call shows "needs review"; advisor labels manually | Service Advisor | Yes |
| A6 kill-switch engaged | `agents.status=paused` | No sentiment run; call note saved raw; manual `/suggest-sentiment` also blocked | Admin | N/A |
| Prompt-injection in call note / inbound reply | `guardUntrusted` sanitization | Untrusted text neutralized before A6; model never executes embedded instructions | System | No |
| Cross-tenant asset access attempt | Asset `dealerId ≠ activeDealerId` | `403`; audit-logs row (dealer-scoped) | System | No |
| Concurrent edits to same intro task (advisor + manager) | Version/updatedAt mismatch on `PATCH /tasks/:id` | `409` conflict; reload latest, re-apply | System | Yes — reload |
| Asset spans multiple divisions (CAM trade-in serviced at GT) | Vehicle division ≠ advisor division | Route to correct-division advisor pool; if cross-division policy, manager assigns manually | Service Manager | Yes |
| Customer is business account, contact left company | Primary contact phone/email bounces | Pull secondary `contacts`; if none, flag account for data refresh | Service Advisor | Yes |
| Duplicate asset from re-run delivery advance | Idempotency key on delivery step | Delivery advance idempotent — no duplicate asset/task created | System | No |
| Timezone / holiday miscount on SLA | Business-day calc | Use dealer working-days calendar in GMT-4; holidays excluded from 5-day count | System | No |
| Odometer entered below delivery reading | `service_orders.odometer` validation | Reject with hint (must ≥ delivery odometer); advisor corrects | Service Advisor | Yes |

**📄 Documents & PDF format**

- **Coverage Plan Certificate (pdfkit):** generated on `POST /coverage`. **Header** — dealer logo, dealer name + division (CAM/GT), "Coverage Certificate", plan number. **Vehicle block** — make/model/trim/year, VIN, engineNumber, registration. **Coverage block** — type (Warranty/AMC), `startsAt`/`endsAt`, mileage cap, inclusions/exclusions. **Totals** — plan price USD + GYD (×`usdExchangeRate`), tax lines from `dealer_taxes` (VAT 0%/14% by model, EV exclusions). **Footer** — GRA-compliant note (GYD), terms, advisor name, issue date (GMT-4). Delivery: email + WhatsApp via outbox.
- **Service Reminder / Intro message (template, not PDF):** HTML email template + WhatsApp text via `email_logs` outbox, dedupeKey per send. Fields: customer name, vehicle, advisor name + direct line, next scheduled service date, coverage highlights. A7-drafted, human-approved.
- **Service Order confirmation (pdfkit, optional):** on `POST /service-orders` — header (dealer/division, order number), customer + vehicle block, scheduled date/time, complaint/type, odometer, assigned advisor, jobs[] placeholder. Delivered on request via `/documents/:id/download` (presigned GCS, per-object ACL, dealer-scoped).
- **Handoff timeline (system, no PDF):** `timeline_events` entries — asset created, advisor assigned, intro attempts, cadence set — viewable in console, exportable via `/reports`.
