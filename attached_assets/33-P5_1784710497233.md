# Platform P5 — Isolation Guarantees & Platform API Index

This section is the authoritative reference for the **control-plane surface** (`/platform/*`, super-admin only) and the **dealer settings surface** (`/admin/*`, dealer `settings:admin`), and for the tenant-isolation invariants that every other section depends on. Isolation is not a feature of one module — it is a property of the request pipeline that **all 163 paths** inherit. See `P1` for the tenancy data model (`dealers`, `dealer_users`, `divisions`), `P2`/`P3` for RBAC and JIT provisioning, `P4` for entitlements/feature-flags/kill-switches, and `R2` for how data-plane modules consume `activeDealerId(res)`.

## 1. Control-plane vs data-plane — the two portals

AURA is split into a **Platform Console** (control-plane: onboards and governs dealers) and a **Dealer Workspace** (data-plane: the tenant staff's operational system). The two planes never share a scoping authority. The control-plane authorizes off `SUPER_ADMIN_EMAIL` and the global `users` table; the data-plane authorizes off `dealer_users` membership resolved into `activeDealerId(res)`.

| Property | Control-plane (`/platform/*`) | Data-plane (everything else) |
| --- | --- | --- |
| Authorizing identity | Super-admin (email ∈ `SUPER_ADMIN_EMAIL`) | Signed-in Clerk user with a row in `dealer_users` for the target dealer |
| Scoping key | None — operates **across all tenants** by design | `activeDealerId(res)` injected from validated `x-dealer-id` |
| Membership check | Not applicable (global operator) | `x-dealer-id` MUST ∈ caller memberships, else 403 |
| RBAC evaluated against | Fixed super-admin capability | `role_permissions` (module×category) + `role_field_permissions` |
| Cross-tenant read of a foreign row | Allowed (that is the job) | **404** — no existence leak (see §5) |
| Object-storage namespace | May list any `dealers/{id}/` prefix | Locked to `dealers/{activeDealerId}/` |
| Audit target | `audit_logs` with `actorType=super_admin`, `dealerId=null` or affected dealer | `audit_logs` always stamped with `dealerId=activeDealerId` |

## 2. Secret & credential separation between planes

A compromised dealer-scoped token must never reach control-plane authority, and a dealer's integration credentials must never be reachable from another dealer's session. Secrets are partitioned by plane and by tenant.

| Secret / credential | Owned by | Reachable from | Isolation rule |
| --- | --- | --- | --- |
| `SUPER_ADMIN_EMAIL`, platform service creds | Control-plane env | Server process only | Never sent to any browser; never resolvable by dealer role |
| Clerk backend key / `clerkId` mapping | Global auth layer | Auth middleware only | Identity is global; authorization is per-plane |
| `dealer.usdExchangeRate` | Per-dealer (`dealers`) | Data-plane, own tenant | Read via `activeDealerId`; drives GYD = USD×rate (~209) display only |
| WhatsApp Meta / Twilio / Gmail SMTP+IMAP creds | Per-dealer entitlement config (`P4`) | Data-plane, own tenant only | Webhook events routed to a dealer, then all follow-up scoped; see `R7` (comms) |
| LOS Demerara live/sandbox keys | Per-dealer finance config | Finance module, own tenant | `los_submissions` and `finance_connector` scoped by `activeDealerId`; see `R5` |
| GCS presigned URL signing | Platform storage service | Server issues; client receives short-lived URL | Signer refuses keys outside `dealers/{activeDealerId}/` (§4) |
| Anthropic API key (`claude-sonnet-4-6`) | Platform env | Server-side agent runtime only | Never client-exposed; every call gated by `isAgentEnabled` + `MIN_AGENT_CONFIDENCE`, audited via `recordAgentRun` |
| idempotency keys (money) | Per-dealer (`idempotency_keys`) | Data-plane, own tenant | Key uniqueness scoped by `dealerId` so two tenants cannot collide; see `R5` |
| PENDING-INFRA seams (backups/DR, encryption-at-rest, tracing, broker) | `lib/infra-seams.ts` | Server, no-op today | Seams accept `dealerId` so isolation semantics are preserved when implemented |

## 3. Tenant-isolation invariants — enforcement checklist

Each invariant below is a MUST. A violation is a P0 security defect, not a bug. These are the guarantees every data-plane section (`R2`–`R9`) relies on rather than re-implementing.

| # | Invariant | Enforced at | Failure mode if absent |
| --- | --- | --- | --- |
| I1 | `activeDealerId(res)` is injected on **every** data-plane request by middleware — no handler reads `x-dealer-id` raw | Tenancy middleware | Handler forgets scope → cross-tenant read |
| I2 | `x-dealer-id` header MUST resolve to a row in the caller's `dealer_users`; otherwise **403** | Tenancy middleware | Any user impersonates any dealer |
| I3 | Every DB query on a tenant-owned table is filtered by `dealerId = activeDealerId` — including joins and sub-selects | Repository layer | Foreign rows leak via relations |
| I4 | A read/write targeting a row that exists but belongs to another dealer returns **404** (no existence leak), never 403, at the data-plane | Repository + handler | Enumeration reveals foreign IDs |
| I5 | 403 is returned ONLY where membership itself is the check (I2) or RBAC denies a permitted-tenant action | Middleware / RBAC | Mixing 403/404 leaks which rows exist |
| I6 | Object-storage keys are namespaced `dealers/{activeDealerId}/…`; the presigner rejects any other prefix (corrected: storage ACL is dealer-scoped) | Storage service | Cross-tenant document/asset access |
| I7 | `/audit-logs` reads are scoped to `activeDealerId` (corrected: audit-logs are dealer-scoped for dealer users) | Audit handler | One dealer reads another's audit trail |
| I8 | Concierge (SSE + copilotkit, nav-only) is dealer-scoped — its context, retrieval, and suggestions all filter by `activeDealerId` (corrected) | Concierge runtime | AI surfaces another tenant's data |
| I9 | Every AI call PII-minimizes, runs `guardUntrusted` on ALL untrusted text, checks `isAgentEnabled`, enforces `MIN_AGENT_CONFIDENCE`, and writes `agent_runs` via `recordAgentRun` — all stamped with `dealerId` | Agent runtime | Prompt-injection / cross-tenant context / silent low-confidence output |
| I10 | Division axis (CAM/GT) is a **second** filter within a dealer, never a substitute for I3 | Repository layer | Division scoping mistaken for tenant scoping |
| I11 | Money idempotency keys are unique **per dealer**; a replayed key from another tenant never matches | `idempotency_keys` constraint | Cross-tenant idempotency collision |
| I12 | Impersonation is audited and role-based (corrected: raw `AUTH_BYPASS` / `x-test-user-email` retired); every impersonated action writes `audit_logs` with the real actor | Auth + audit | Untraceable privileged access |
| I13 | Reports and dashboards aggregate **server-side** under `activeDealerId` — clients never receive foreign rows to aggregate (corrected) | Reports service | Row-level leak through analytics |
| I14 | Webhook events (Meta/WhatsApp/Twilio) are resolved to exactly one dealer before any data-plane write; unresolvable events are quarantined in `webhook_events` | Webhook router | Inbound message written to wrong tenant |
| I15 | `PATCH /agents` (kill-switch / status) is gated at **governance level**, not ordinary edit (corrected) | RBAC (governance) | Line staff disable/enable agents |

## 4. Object-storage namespacing (I6 detail)

- All keys follow `dealers/{dealerId}/{module}/{entityId}/{filename}` — e.g. `dealers/CAM/customer_documents/…`, `dealers/GT/deliveries/pdi/…`.
- Presigned-URL issuance (`/storage/*`) derives the prefix from `activeDealerId(res)`; a client-supplied key outside that prefix is rejected before signing.
- Applies to `customer_documents`, `finance_documents`, `documents`, delivery PDI photos, quote/invoice/PDI PDFs (pdfkit), and vehicle import artifacts.
- GRA extract inputs/outputs are stored under the owning dealer's prefix; the GRA vision extract (Guyana) reads only legible fields and never fabricates — duty is server-computed and human-gated (see `R6`).

## 5. Control-plane API index — /platform/* (SUPER-ADMIN only)

| Method & path | Request | Response | RBAC / notes |
| --- | --- | --- | --- |
| `GET /platform/dealers` | query: `status?`, `country?`, pagination | `[{id,name,city,country,status,usdExchangeRate,createdBy,createdAt}]` | Super-admin. Cross-tenant listing is intended. |
| `POST /platform/dealers` | `{name,city,country,usdExchangeRate}` | `201 {id,…,status:'active',createdBy}` | Super-admin. Onboards a tenant; seeds `divisions` (CAM/GT), default `roles`, entitlements, agent rows. |
| `GET /platform/dealers/:id` | path `id` | `{…dealer, entitlements, featureFlags}` | Super-admin. |
| `PATCH /platform/dealers/:id` | `{name?,city?,status?,usdExchangeRate?}` | `200 {…dealer}` | Super-admin. Status/rate changes audited (`audit_logs`). |
| `GET /platform/dealers/:id/members` | path `id` | `[{userId,roleId,isGeneralManager,divisionId,reportingManagerUserId,lastLeadAssignedAt}]` | Super-admin. Reads `dealer_users` for that tenant. |
| `POST /platform/dealers/:id/members` | `{userId,roleId,divisionId?,isGeneralManager?,reportingManagerUserId?}` | `201 {…membership}` | Super-admin. Grants membership; first-user-becomes-GM is retired (see `P3`). |
| `PATCH /platform/dealers/:id/members/:userId` | `{roleId?,divisionId?,isGeneralManager?,reportingManagerUserId?}` | `200 {…membership}` | Super-admin. |
| `DELETE /platform/dealers/:id/members/:userId` | path | `204` | Super-admin. Revokes membership (I2 immediately re-denies). |
| `GET /platform/users` | query `email?`, `clerkId?` | `[{id,clerkId,email,name,createdAt}]` | Super-admin. Global `users` — identity is cross-tenant; authority is not. |
| `GET /platform/users/:id` | path | `{…user, memberships:[{dealerId,roleId,…}]}` | Super-admin. Shows the user's memberships across all dealers. |

## 6. Dealer-settings API index — /admin/* (dealer settings:admin) + /audit-logs

These are data-plane admin endpoints: fully scoped by `activeDealerId`, requiring the `settings` module at `admin` category in `role_permissions`. They configure the tenant, not the platform.

| Method & path | Request | Response | RBAC / notes |
| --- | --- | --- | --- |
| `GET /admin/users` | query pagination | `[{userId,email,name,roleId,divisionId,isGeneralManager}]` | `settings:admin`. Own-tenant members only (join `dealer_users`). |
| `PATCH /admin/users/:userId` | `{roleId?,divisionId?,reportingManagerUserId?}` | `200` | `settings:admin`. Cannot self-onboard a new global user (that is `/platform/users`). |
| `GET /admin/roles` | — | `[{id,name,isSystem}]` | `settings:admin`. Scoped to dealer. |
| `POST /admin/roles` | `{name}` | `201 {id,name}` | `settings:admin`. |
| `PATCH /admin/roles/:id` · `DELETE /admin/roles/:id` | `{name?}` / — | `200` / `204` | `settings:admin`. System roles not deletable. |
| `GET /admin/roles/:id/permissions` | path | `[{module,category,view,create,edit,delete,admin}]` | `settings:admin`. See `P2` for module/category matrix. |
| `PUT /admin/roles/:id/permissions` | `[{module,category,view,create,edit,delete,admin}]` | `200` | `settings:admin`. Writes `role_permissions`. |
| `GET /admin/roles/:id/field-permissions` | path | `[{module,field,access:hidden\|view\|edit}]` | `settings:admin`. `role_field_permissions`. |
| `PUT /admin/roles/:id/field-permissions` | `[{module,field,access}]` | `200` | `settings:admin`. Governs field-level masking (e.g. finance PII). |
| `GET /admin/lead-sources` · `POST` · `PATCH/:id` · `DELETE/:id` | `{name,channel,isActive?}` | `[…]` / `201` / `200` / `204` | `settings:admin`. Feeds `lead_sources`; ties to Meta Lead Ads + enquiries (see `R2`). |
| `GET /admin/stage-checklists` · `POST` · `PATCH/:id` | `{stage,version,items:[{key,label,required}]}` | `[…]` / `201` / `200` | `settings:admin`. Versioned; drives `POST /leads/:id/advance → 422 {unmet:[]}` (see `R2`) and the single Advance CTA. |
| `GET /admin/taxes` · `POST` · `PATCH/:id` · `DELETE/:id` | `{name,rate,appliesTo}` | `[…]` / `201` / `200` / `204` | `settings:admin`. `dealer_taxes`; A3 quote codegen computes deterministically (see `R4`). |
| `GET /audit-logs` | query `actorId?,entity?,action?,from?,to?` | `[{id,dealerId,actorType,actorId,action,entity,entityId,before,after,createdAt}]` | Dealer users: scoped to `activeDealerId` (I7). Includes impersonation records (I12) and governance changes (I15). |

**Note:** Per-dealer agent kill-switches and feature-flags are governed under `P4`; `PATCH /agents` and `/agents/runs/:id/review` are gated at governance level (I15), distinct from `settings:admin`. Do not conflate them.

## 7. Cross-tenant negative-test suite — attempts that MUST fail

These are contract tests the enterprise build MUST keep green. Each asserts the exact status and the absence of any foreign data in the body. "404 (no leak)" means the body is a generic not-found, never a 403 that would confirm the row exists.

| # | Attempt | Required result | Invariant |
| --- | --- | --- | --- |
| N1 | Dealer-A user sends `x-dealer-id: B` where B ∉ memberships | **403** | I2, I5 |
| N2 | Dealer-A user requests `GET /customers/:id` where the customer belongs to dealer B | **404** (no leak) | I3, I4 |
| N3 | Dealer-A user requests `GET /leads/:id` for a B-owned lead, then tries `POST /leads/:id/advance` | **404** on both | I3, I4 |
| N4 | Dealer-A user requests a presigned URL for key `dealers/B/customer_documents/x.pdf` | **403**/reject at signer | I6 |
| N5 | Dealer-A user fetches a GCS object using a URL presigned for dealer B | **403**/expired-scope | I6 |
| N6 | Dealer-A user calls `GET /audit-logs` and expects to see B's actions | Only A's rows (B absent) | I7 |
| N7 | Dealer-A user asks concierge (SSE) about "customer Ramnarine at GT Automotive" while in CAM tenant | No B data; retrieval scoped to A | I8 |
| N8 | Prompt-injection payload in an inbound WhatsApp/email body attempts to exfiltrate other-tenant context via an agent | Neutralized by `guardUntrusted`; nothing cross-tenant surfaced | I9 |
| N9 | Agent output below `MIN_AGENT_CONFIDENCE` is auto-applied without HITL | Blocked; routed to human gate / `gates` | I9 |
| N10 | Ordinary dealer user (no governance) calls `PATCH /agents/:id` to flip `isAgentEnabled` | **403** | I15 |
| N11 | Dealer-A user calls any `/platform/*` endpoint (not super-admin) | **403** | §1, §5 |
| N12 | Dealer-A user replays a money idempotency key that dealer B used on `POST /payments` | No match; A processes independently | I11 |
| N13 | Dealer-A user forces a division filter `divisionId=GT` to reach a B row | **404** (dealer filter still applies first) | I3, I10 |
| N14 | Request omits `x-dealer-id` entirely on a data-plane path | **400/403** — no default tenant | I1, I2 |
| N15 | Caller uses retired `x-test-user-email` / `AUTH_BYPASS` to impersonate | Rejected; only audited role-based impersonation permitted | I12 |
| N16 | Dealer-A user pulls `GET /reports/*` or `GET /dashboard/*` expecting client-side access to B rows | Server-side aggregate over A only; no foreign rows in payload | I13 |
| N17 | Inbound webhook (`/webhooks/meta\|whatsapp\|twilio`) that cannot be resolved to a single dealer | Quarantined in `webhook_events`; no data-plane write | I14 |
| N18 | Dealer-A user requests `GET /vehicles/:id`, `GET /deals/:id`, `GET /finance-applications/:id`, `GET /service-orders/:id` for B-owned rows | **404** on every entity (uniform) | I3, I4 |
| N19 | Dealer-A user edits `role_field_permissions` to unmask a finance field, then reads a B finance app | Field rules apply within A only; B row still **404** | I3, I4 |
| N20 | Super-admin token used against a data-plane write without a valid `x-dealer-id` | **403** — platform authority does not auto-scope data-plane mutations | §1, I2 |

## 8. How other sections rely on P5

- **R2 (Leads/CRM):** assumes I3/I4 so `/leads`, `/customers`, notes, and the single Advance CTA never span tenants; stage-checklist config lives in `/admin/stage-checklists` (§6).
- **R4 (Deals/Quotes):** A3 tax codegen reads `/admin/taxes` (§6); below-floor and VIN-lock gates write `gates` under `activeDealerId`.
- **R5 (Finance/Money):** depends on I11 idempotency scoping and LOS credential separation (§2); no payment gateway — ledger only.
- **R6 (GRA/Compliance):** Guyana duty is server-computed and human-gated; AI extracts legible fields only, under I6/I8/I9.
- **R7 (Comms):** webhook resolution (I14) and per-dealer WhatsApp/Twilio/Gmail creds (§2) keep inbound traffic tenant-correct.
- **P4 (Governance):** owns kill-switches and feature-flags; P5 only asserts that flipping them is governance-gated (I15) and audited (I12).
