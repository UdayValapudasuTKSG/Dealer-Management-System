# Reference R3 — Agent Catalog

This catalog is the **complete and closed** enumeration of every automated actor in AURA. There is no "A1–A27" range; the agents listed below *are* the whole catalog. Each actor belongs to exactly one of three classes:

- **Autonomous LLM writers** — internal-only, fully audited, individually kill-switchable. These are the *only* actors permitted to write to the data plane on their own authority. Exactly three exist: `A1 intake_dedup`, `A6 call_sentiment`, `A16 case_classifier`.
- **Deterministic SYSTEM actions** — plain transactional code (NOT LLM). They run *inside* the request/DB transaction, are *not* "AI writes", and are *not* kill-switchable. Exactly three: `A2 round_robin`, `A3 quote_tax`, `A11 vin_allocation`.
- **HITL / advisory LLM** — never write or send to a customer without a human decision. They draft, suggest, extract, or navigate; a human commits.

All LLM actors use Anthropic `claude-sonnet-4-6`. Every actor is dealer-scoped: an agent invoked under **activeDealerId** may only read/write rows within that dealer scope (foreign rows are **404**, never **403**; see [r4](#r4)). Entitlement/feature-flag gating applies after RBAC — a non-entitled agent module for a dealer resolves to **404** (INV-ENT-1, see [r9](#r9)).

## R3.1 — Class 1: Autonomous LLM Writers (the only autonomous AI writers)

These three may create/modify data-plane rows without a per-action human approval. Every run is recorded in `agent_runs` with inputs, model output, and resulting mutations, and each is independently disableable via `isAgentEnabled(semanticKey)`. When disabled, the surrounding flow degrades gracefully (manual fallback), never blocks.

| ID | Agent | Semantic Key | Trigger | Writes (autonomous) | Audit / Governance |
| --- | --- | --- | --- | --- | --- |
| A1 | intake_dedup | `intake_dedup` | Inbound lead from Meta LeadAds / WhatsApp / Gmail IMAP intake. | Creates or merges `leads`/`contacts`; sets `lead_sources`; dedup-links to existing customer/contact. | Every merge/create logged to `agent_runs` + `timeline_events`. Kill-switch → new intake queued for manual triage. |
| A6 | call_sentiment | `call_sentiment` | Completed call recording/transcript in `call_logs` (Twilio Voice). | Writes sentiment score/labels back onto `call_logs` and rolls into lead/customer signals. | Logged in `agent_runs`. Kill-switch → sentiment fields left null; downstream digest skips. |
| A16 | case_classifier | `case_classifier` | New/updated service case (`service_cases`; built app reused `service_orders`, see [r8](#r8)/X1). | Sets case category / priority / routing classification on the Case. | Logged in `agent_runs`. Kill-switch → case opens `open` with null classification for manual routing. |

## R3.2 — Class 2: Deterministic SYSTEM Actions (plain code, NOT LLM, NOT kill-switchable)

These execute as ordinary code paths inside the transactional flow. They are deterministic, reproducible, and carry no model call. They must never be described as "AI writes" and have **no** kill-switch key.

| ID | Action | Runs inside | Deterministic behavior |
| --- | --- | --- | --- |
| A2 | round_robin | Lead assignment flow (`POST /api/leads/:id/assign` and auto-assign on intake). | Deterministically selects the next eligible sales user within the dealer per the round-robin/workload rule; writes `leads.ownerId`. No LLM. |
| A3 | quote_tax | Quote build/recalc (`POST /api/leads/:id/quote`, quotes). | Computes taxes/fees deterministically from `dealer_taxes`; money at USD scale, GYD display via **usdExchangeRate**. GRA duty is server-computed, never fabricated (see A-gra_extract below and [r7](#r7)). |
| A11 | vin_allocation | Deal commit transaction (`deals`: desking → committed, see [r2](#r2)). | On commit, deterministically locks a specific VIN and transitions `vehicles.status` → `booked`. VIN allocation is **NOT a gate** and there is no AI/VIN gate — the only human decision is the deal-commit itself (which fires the `below_floor_price` gate only if discounted below floor; see [r2](#r2), NC-4). |

## R3.3 — Class 3: HITL / Advisory LLM (never write/send without a human)

These draft, suggest, extract, or navigate. A human reviews and commits every outbound or state-changing action. Each LLM actor in this class is kill-switchable where noted.

| ID | Agent | Semantic Key | Role | Human control point |
| --- | --- | --- | --- | --- |
| A5 | doc_prefill | `doc_prefill` | Pre-fills document/form fields (quotes, deal docs, delivery paperwork) from known data. | Human reviews and confirms before the document is saved/generated (INLINE REVIEW, not a gate — NC-4). |
| A7 | outreach | `outreach` | Drafts customer outreach (email / WhatsApp) — `POST /api/leads/:id/outreach`. | **Approve&Send**: nothing leaves the system until a human approves; send is async (**202**, NC-1). Hard-blocked under impersonation (NC-10). |
| A10 | test_drive_availability | `test_drive_availability` | Suggests test-drive slots / checks availability (`/api/leads/:id/availability-check`, `test_drives` entity — see X1). | Advisory only; human books. Booking soft-locks a vehicle to `reserved` (see [r2](#r2)). |
| A15 | pipeline_suggestions | `pipeline_suggestions` | Suggests next-best pipeline actions (`/api/pipeline/suggestions`). | Advisory; user chooses whether to act. No autonomous state change. |
| — | sentiment_digest | `sentiment_digest` | Aggregates sentiment signals into a periodic digest. | Read/rollup only; surfaced to humans, no customer send. |
| — | persona_recommend | `persona_recommend` | Recommends customer persona (`/api/customers/:id/persona/recommend`). | Advisory; human accepts/edits the persona. |
| — | concierge | `concierge` | In-app conversational assistant (Anthropic conversations / CopilotKit). | **Navigation-only**: guides/answers within dealer scope; performs no writes and no cross-tenant reads. |
| — | gra_extract | `gra_extract` | Extracts *legible fields only* from GRA documents (`/api/gra/extract`). | Feeds a human `gra_filing` gate (NC-4). Never fabricates GRA duty — duty is server-computed ([r7](#r7)). Human resolves the gate. |

## R3.4 — Kill-Switch Registry

Enforcement gate for LLM actors is `isAgentEnabled(semanticKey)`, checked before any model call. The complete set of valid semantic keys is exactly:

- `intake_dedup`, `call_sentiment`, `case_classifier` (autonomous writers)
- `doc_prefill`, `outreach`, `test_drive_availability`, `pipeline_suggestions`, `sentiment_digest`, `persona_recommend`, `concierge`, `gra_extract` (HITL/advisory)

The deterministic SYSTEM actions (`round_robin`, `quote_tax`, `vin_allocation`) have **no** kill-switch key and cannot be disabled — they are core transactional logic.

## R3.5 — Kill-Switch Governance

Toggling an agent kill-switch is a platform-reserved **governance** capability. It is *not* grantable through `/admin/roles` and is *not* equivalent to `settings:admin` (NC-13). It is exercised from the Platform Console control-plane, is fully audited, and is distinct from any dealer-workspace RBAC permission in the [r4](#r4) module vocabulary (module `agents`: view|create|edit|delete|admin governs agent *runs/config visibility*, not the platform governance kill-switch).

## R3.6 — Audit, Impersonation & Invariants

- Every LLM run (both autonomous and advisory) is recorded in `agent_runs`; autonomous writes additionally emit `timeline_events` and `audit_logs`.
- Under super-admin impersonation (READ-ONLY default, ≤60m, reason-logged, **impersonatedBy** stamped — NC-10): agent-driven **customer sends** (A7 outreach), **money-posting**, and **gate-resolution** are HARD-BLOCKED even with elevation.
- Autonomous writers operate internal-only — they never emit external customer communications on their own authority; any customer-facing send always routes through A7's human Approve&Send.
- All agents inherit tenant isolation and entitlement gating: non-entitled agent for a dealer → **404** (INV-ENT-1); suspended tenant blocks data-plane agent writes with **423** while reads remain allowed (NC-1, NC-9).
