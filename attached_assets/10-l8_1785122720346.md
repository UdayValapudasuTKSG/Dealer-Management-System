# Layer 8 — Delivered (Closed Won) Delivery Advisor

**🚦 Flow (step-by-step, lowest level)**

- **1. Open handover console.** `GET /api/deliveries/:id` loads the delivery created at deal commit (Layer 7). Steps `jsonb` render as the 9-step tracker: `sales_order→pdi_checklist→registration→insurance→invoice→appointment→delivery→signature→feedback`. All reads scoped by `activeDealerId(res)` + `x-dealer-id`; cross-division (CAM/GT) delivery is 404, not 403 (tenant isolation).
- **2. Confirm prior steps closed.** Advance is **strictly sequential**: server rejects `POST /:id/advance` with `422 {unmet:[]}` if `registration` (reg plate `^[A-Z]{3}[0-9]{1,4}$`), `insurance`, or `invoice` steps are incomplete. Invoice must already be auto-issued and reconciled against `payments` (no `outstanding-balances` row for this deal).
- **3. Pre-handover damage / PDI re-verify.** Advisor walks the vehicle with customer; if a defect appears since PDI, `PATCH /:id/pdi` re-opens `pdiItems[]` — this **blocks** the `delivery` step until re-passed (see edge table).
- **4. Identity / authorized-rep check.** Advisor confirms the person taking delivery is the `customers` account holder or a recorded authorized rep (contact on account with power-of-attorney doc). Mismatch → hold, do not sign.
- **5. Capture actual delivery date.** Set `deliveredAt` (America/Guyana GMT-4) on the `delivery` step advance — this is the real handover timestamp, not scheduled `appointment` date.
- **6. Signature capture + upload.** Customer signs on-device → `signatureData` (base64 PNG) written; a photographed signed sales-order/handover sheet is uploaded via `POST /api/storage/uploads/request-url` then registered as `documents` (polymorphic `delivery`). **A5 vision OCR** verifies the uploaded sheet's printed name/VIN/reg against the delivery — `extractionStatus:'proposed'`, HITL confirm.
- **7. Advance `signature→feedback`.** `POST /:id/advance`. On the terminal `delivery`/`feedback` transition the server **atomically**: (a) sets `vehicles.status='delivered'` (VIN-locked since commit); (b) ensures the auto-invoice is `issued→paid`; (c) **creates the Asset** row (`assets`: `accountId, vehicleId, dealId, deliveryId, deliveredAt`); (d) **assigns a Service Advisor** (`assets.serviceAdvisorUserId`) via round-robin over the delivering division's advisors; (e) writes `timeline_events` and flips `deals.stage='delivered'` + lead `phase` closed-won.
- **8. Feedback / CSAT survey within 24h.** Advance enqueues a survey to the customer's channel via `email_logs` outbox (email + WhatsApp), `dedupeKey=delivery:{id}:csat`. Survey landing writes `deliveries.feedbackRating` + first-class Review/CSAT record. SLA timer starts at `deliveredAt`.
- **9. Deliver invoice PDF.** `GET /:id/invoice.pdf` (pdfkit) attached to the delivery-confirmation email and offered on-screen; WhatsApp gets a link (outbox).

**⚙️ Agents in play**

- **A5 Document pre-fill (vision, claude-sonnet-4-6)** → trigger: signed-handover upload registered as `documents` → grounded inputs: the uploaded object bytes only, allowlist `PREFILL_FIELDS` (printed name, `vin`, `registration`) compared against `deliveries.dealId→deals.vehicleId` and `customers` — **extracts legible fields only, never invents VIN/reg** → output `{extraction:{name,vin,registration},confidence}` with `extractionStatus:'proposed'` → HITL: **yes**, advisor confirms via `/documents/extraction/review`; below `MIN_AGENT_CONFIDENCE` the extraction is flagged for manual entry, never auto-accepted. Untrusted OCR text wrapped in `guardUntrusted`. Run recorded to `agent_runs`; kill-switch `agents.status='paused'` falls back to manual field entry.
- **A2 Round-robin assign (deterministic, not LLM)** → trigger: terminal advance creating the Asset → inputs: `dealer_users` filtered to Service Advisor role in the **delivering division**, ordered by `lastLeadAssignedAt` → output: `assets.serviceAdvisorUserId` set + `lastLeadAssignedAt` bumped → HITL: no (deterministic), but reassignable by manager.
- **A6 Call sentiment (fire-and-forget)** → not primary here; if a delivery-day call note is logged it scores `call_logs.sentiment`. Declared, audited, kill-switchable; `guardUntrusted` on transcript.

**🧠 AI for the persona**

- **Signature-sheet verification banner**: "OCR name `Ravi Persaud` and VIN `…4821` match this delivery" — or a red mismatch flag prompting manual review before the advisor can advance.
- **Readiness check (not "Run Review")**: inline console shows which of registration/insurance/invoice are green and exactly what is `unmet`, so the single **"Advance to Delivered"** CTA is either enabled or explains why.
- **Concierge (SSE, nav-only)**: "show this customer's other assets / warranty coverage" — dealer-scoped grounding, no mutations.
- Suggested Service-Advisor intro draft for the CSAT/welcome message — human **Approve & Send** only (A7 pattern, never auto-send).

**🔑 Key fields · validations · SLA**

- `deliveries.steps` jsonb — 9-step, sequential; server enforces order, advance returns `422 unmet[]` otherwise.
- `signatureData` — required non-empty base64 PNG before `signature` step closes; `deliveredAt` — required, must be ≥ registration date, GMT-4.
- `vehicles.registration` `^[A-Z]{3}[0-9]{1,4}$`; `vin`/`engineNumber` exactly 17 chars, VIN-locked since commit — immutable at delivery.
- `assets` created exactly once (idempotent on `deliveryId`); `serviceAdvisorUserId` mandatory on create.
- **SLA**: CSAT survey enqueued ≤ 24h from `deliveredAt` (outbox `dedupeKey=delivery:{id}:csat`, retry/backoff); invoice PDF delivered same session.
- Money: `invoices` stored USD-scale, PDF shows GYD = amount × `dealers.usdExchangeRate`; tax lines from `dealer_taxes` (VAT 0/14%, duty) computed server-side — never AI.
- All mutations carry `Idempotency-Key`; every write emits `timeline_events` (`isAgent` flagged when agent-sourced).

**🔀 Edge-of-edge cases → handling**

| Scenario | Detection | Handling | Owner | HITL? |
| --- | --- | --- | --- | --- |
| Reject-at-handover (customer refuses vehicle) | Advisor marks refusal before signature | Do not advance; keep `vehicles.status='delivered'` UNset (stays `booked`); open task + timeline note; deal stays `committed`; no Asset created | Delivery Advisor / Sales Mgr | Yes |
| Damage found pre-handover | `PATCH /pdi` item `pass:false` + photos | Blocks `delivery` step; log `gates` if remediation cost impacts price; reschedule appointment; vehicle stays reserved | Delivery Advisor | Yes |
| Authorized rep, not account holder | Rep identity ≠ `customers`/`contacts` record | Require POA doc upload (A5 verify) + `authorizedRep.contactId` on advance; else block signature | Delivery Advisor | Yes |
| Signature OCR mismatch / low confidence | A5 name/VIN ≠ delivery OR confidence < `MIN_AGENT_CONFIDENCE` | Red banner; force manual `/extraction/review`; cannot advance on unconfirmed extraction | Delivery Advisor | Yes |
| Outstanding balance at delivery | `/outstanding-balances` row for deal | `invoice` step / advance `422 unmet:['balance_due']`; collect `payments` (idempotent recompute) first | Cashier / Advisor | Yes |
| Double-advance / duplicate submit | Same `Idempotency-Key` | Return prior result; single Asset, single invoice, single CSAT enqueue | System | No |
| Concurrent advisors on same delivery | Optimistic version / step conflict | 409 on stale step; reload console; last-writer re-validates gates | System | No |
| CSAT WhatsApp opt-out / failed delivery | Outbox status `failed`/opt-out flag | Fall back email; `/emails/logs/:id/retry` backoff; after N attempts create manual follow-up task | System / Advisor | Partial |
| Soft-lock (`holdUntil`) expiry mid-handover | Hold lapsed while completing steps | VIN already locked at commit (status `booked`) so no re-sale race; advance proceeds | System | No |
| Cross-tenant / cross-division access | `activeDealerId`/division mismatch | 404 (not 403); every query dealer-scoped incl. storage per-object ACL | System | No |
| Wrong Service Advisor auto-assigned | Advisor on leave / wrong division | Manager reassigns `assets.serviceAdvisorUserId`; timeline logged | Service Mgr | Yes |
| Agent kill-switch active (A5 paused) | `agents.status='paused'` | Skip OCR; advisor enters/verifies fields manually; advance still allowed | Delivery Advisor | Yes |
| Registration/insurance revoked after issue | Reg step reopened | Blocks advance `422`; re-file GRA (type `gra_filing` gate) before delivery | Admin / Advisor | Yes |
| Late/never CSAT response | No `feedbackRating` >24h | Delivery still complete; open reminder task; digest surfaces in `/dashboard/sentiment` | Service Advisor | Partial |

**📄 Documents & PDF format**

- **Delivery Invoice PDF** (`pdfkit`, `GET /:id/invoice.pdf`) — **Header**: dealer logo + name (CAM Motors / GT Automotive), division, dealer TIN, `invoiceNumber`, issue date (GMT-4), status stamp. **Bill-to**: customer name, account no, address. **Vehicle**: make/model/trim/year, `vin`, `engineNumber`, `registration`, odometer. **Line items** (cols: Description · Qty · Unit GYD · Amount GYD): vehicle price, accessories[], trade-in credit (negative), discount. **Tax block**: VAT (0%/14% per `dealer_taxes`), import duty, excise — server-computed, EV exclusions noted. **Totals**: subtotal, tax total, `otdPrice`, deposit/payments applied, balance = 0. **Footer**: payment methods received, GYD/USD rate used, "Guyana Revenue Authority" note, terms, advisor signature line. Delivery: attached to confirmation email + WhatsApp link (outbox).
- **Signed Handover / Sales-Order sheet** — uploaded scan stored as `documents` (scope delivery, dealer-ACL object); A5 OCR-verified; carries `signatureData` + printed name + VIN.
- **Delivery Confirmation email/WhatsApp** — HTML template via nodemailer/outbox: vehicle summary, Asset created, assigned Service Advisor name + contact, coverage plan, CSAT survey link (24h SLA).
- **CSAT Survey** — first-class Review record writing `deliveries.feedbackRating`; results feed `/dashboard/sentiment` digest.
