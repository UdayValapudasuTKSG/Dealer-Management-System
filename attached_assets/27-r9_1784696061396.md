# Reference R9 — Corrected-Design Deltas (spec vs built app)

**Scope of this reference (per NC-12).** R9 catalogs **defects in the BUILT application** — places where the shipped AURA code diverges from the corrected mandate — each expressed as `as-built DEFECT → corrected MANDATE → status → severity → where`. Every status here is `to-fix (in app)`: the corrected design is authoritative (see r1–r8, r10), and the app must be brought into conformance. R9 is **NOT** the same as V4. `V4` enumerates **residual open items of the spec/infra** — the PENDING-INFRA / non-functional blockers (DR/backup, encryption-at-rest, HA/uptime, distributed tracing, durable message broker) that are pre-GA blockers and are explicitly out of the "foolproof" claim. "Foolproof" (NC-12) = application-logic correctness plus tenant/money/AI invariants only; R9 defects fall inside that boundary and are fixable in application code, whereas V4 items require infrastructure work and do not assert production/NFR readiness.

## R9.1 — Legend

| Column | Meaning |
| --- | --- |
| **DEFECT (as-built)** | Observed behavior of the shipped app that violates the corrected design. |
| **MANDATE (corrected)** | The required target-state behavior, stated verbatim against the Normative Contract. |
| **STATUS** | Always `to-fix` — R9 is a defect ledger, not a residual-risk log (that is V4). |
| **SEV** | S1 (tenant/money/AI-safety breach) · S2 (correctness/state-machine) · S3 (contract/label/UX drift). |
| **WHERE** | Layer(s) requiring change and the governing reference anchor. |

## R9.10 — Invariants Introduced / Reasserted by the Corrected Design

| Invariant | Statement | Enforced |
| --- | --- | --- |
| `INV-TEN-1` | No data-plane query executes without the active-dealer predicate; foreign rows are 404, never 403. | Server-side query layer |
| `INV-ENT-1` | Un-entitled module/agent for a dealer is invisible: entitlement gate after RBAC returns 404 (NC-9). | Server-side pipeline gate |
| `INV-MON-1` | Payments are append-only; corrections are offsetting entries; invoices never `draft`. | Ledger + invoice state guard |
| `INV-GRA-1` | GRA duty is server-computed by Guyana authority; never fabricated by app or agent; human `gra_filing` gate required. | gra flow + gates |
| `INV-AI-1` | Only A1/A6/A16 write autonomously (audited, kill-switchable); all other agents are HITL/advisory; deterministic A2/A3/A11 are plain code. | Agent runners |
| `INV-IMP-1` | Impersonation is read-only, ≤60m, reason-logged; money-posting, gate-resolution, customer-sends hard-blocked. | Impersonation service + write guards |

**Relationship to V4.** Once every R9 row reaches conformance, the "foolproof" claim (application-logic correctness + tenant/money/AI invariants) holds. Production readiness still depends on the separate V4 residual list (PENDING-INFRA: DR/backup, encryption-at-rest, HA/uptime, distributed tracing, durable message broker) — those are the pre-GA blockers and are NOT claimed as ready by this spec (NC-12).
