# Layer 4 — Pre-Book (Order Confirmed / reservation) Sales Advisor

**🚦 Flow (step-by-step, lowest level)**

- **1. Lock the model.** Advisor sets `leads.selectedModel` and confirms `interestedVehicleId` via `PATCH /api/leads/:id`. Every write is scoped by `activeDealerId(res)` + `x-dealer-id`; division (CAM/GT) carried on the lead.
- **2. Resolve the buyer to an account.** Advisor searches existing customers (`GET /api/customers?q=`). **Agent A1 Intake/Dedup** proposes matches (phone/email/name/business TIN). Advisor either links an existing `customers.id` or creates one via `POST /api/customers` (`accountType person|business`). Household/business hierarchy set via `parentAccountId`; relationships confirmed at `PUT /api/customers/:id/relations`.
- **3. Attach primary contact.** `POST /api/customers/:id/contacts` with `isPrimary=true` (person = self; business = signatory). Merge duplicates only after human confirm (A1 is HITL here — never auto-merges accounts with assets/deals).
- **4. Soft-lock the vehicle.** On booking intent the vehicle moves `available → reserved` with `holdUntil` + `holdReason='booking'` (soft-lock), preventing another advisor from double-booking the same VIN.
- **5. Take the reservation fee (mandatory) OR trusted bypass.** `POST /api/bookings` creates the RESERVATION (`bookingAmount`, `expiresAt`). Fee is collected via `POST /api/payments` under an `idempotency_keys` guard → recomputes invoice + emits `receipts`. On success `leads.reservationFeePaid=true`. **Trusted bypass** (fleet/repeat VIP, manager-approved) records a `gate`-backed waiver instead of cash and still sets `reservationFeePaid=true` with `bookingAmount=0` + `waiverReason`.
- **6. Create deal desking.** `POST /api/deals` at `stage='desking'` linking `leadId + customerId + vehicleId`; seeds `vehiclePrice`, `tradeInValue` (from appraisal passthrough), `discount`, `otdPrice`. Discount >5% will later trip the `below_floor_price` gate (Layer 5) — flagged now, not blocked.
- **7. Advance the stage — the ONE primary CTA.** Single button **"Advance to Booked"** calls `POST /api/leads/:id/advance`. Readiness (the merged former "Run Review") is shown inline in the Workflow console; if `stage_checklists` gates fail it returns `422 {unmet:[]}` (e.g. fee unpaid, no primary contact, no selectedModel).
- **8. Verbal-commit follow-up.** A `tasks` row is created for the advisor with an SLA timer; **Agent A7 Outreach composer** drafts a confirmation message; advisor "Approve & Send" via `POST /api/leads/:id/whatsapp` or `/outreach` (never auto-sent). Outbound queued to the `email_logs` outbox.

**⚙️ Agents in play**

- **A1 Intake/Dedup** (claude-sonnet-4-6) → trigger: advisor opens customer resolver / creates account → inputs: `customers`, `contacts`, `leads` rows within `activeDealerId` only (dealer-scoped grounding) → output: `{dedupCandidates:[{customerId, score, matchedOn:['phone','email','tin']}]}` → **HITL: yes** — advisor confirms link/merge; A1 never merges accounts that own `assets`/`deals` autonomously. Below `MIN_AGENT_CONFIDENCE` → shown as "possible match, review" not applied.
- **A3 Quote/Code** (deterministic tax engine + pdfkit) → trigger: deal desking created / fee receipt → inputs: `dealer_taxes` (VAT 0%|14%, duty), `vehicles.price`, `dealer.usdExchangeRate` → output: server-computed `otdPrice`, GYD figures, receipt PDF → **HITL: no** (deterministic; no LLM invents tax).
- **A7 Outreach composer** → trigger: verbal-commit follow-up task created → inputs: `leads`, `bookings.expiresAt`, `customer_personas` (dealer-scoped) → output: `{headline, riskLevel, actions[], draftMessage}` → **HITL: yes** — advisor "Approve & Send"; never auto-sends. Untrusted prior inbound text wrapped with `guardUntrusted` before prompting.
- **A2 Round-robin** → deterministic (`dealer_users.lastLeadAssignedAt`); no LLM. Already-assigned lead re-checked for ownership only.
- Every AI call: `isAgentEnabled` kill-switch check → `recordAgentRun` to `agent_runs` (runType, inputSummary, outputSummary, confidence, latency) → PII-minimized inputs.

**🧠 AI for the persona**

- **Dedup suggestions:** "This buyer matches an existing CAM Motors account (Sharma Household) — link instead of create?" with match reasons and confidence badge.
- **Persona-fit nudge:** from `/customers/:id/persona` — "Repeat buyer, loyaltyTier=Gold, LTV GYD 4.2M — eligible for trusted fee bypass" (advisor decides).
- **Agent brief on the console:** headline + riskLevel (e.g. "Verbal commit, fee unpaid 26h — reservation expires in 22h") and a ready draftMessage for one-click approve.
- **Readiness inline:** the merged Workflow console lists exactly which `stage_checklists` gates are unmet before the single "Advance to Booked" CTA.

**🔑 Key fields · validations · SLA**

- `leads.selectedModel` (required to advance), `interestedVehicleId`, `reservationFeePaid` (bool gate), `stageEnteredAt`.
- `customers.accountType ∈ {person, business}`; business requires `tin`; `parentAccountId` must be same-dealer (cross-tenant rejected 403).
- `contacts.isPrimary` — exactly one per account (`422 primary_exists` on second).
- `bookings.bookingAmount` ≥ dealer min (or 0 with `waiverReason` on trusted bypass); `expiresAt` default now+72h (dealer-config); `status active|converted|expired|cancelled`.
- `payments.method` enum (no gateway — internal ledger); `idempotencyKey` mandatory; recompute invoice → `receipts`. Money stored USD-scale; GYD display = amount × `dealer.usdExchangeRate` (~209).
- `deals.discount >5%` sets `belowFloorFlag` (gate enforced at commit, Layer 5), `otdPrice` server-computed from `dealer_taxes`.
- **SLA:** vehicle soft-lock `holdUntil` = fee-window; verbal-commit follow-up `tasks.dueAt` = +24h; reservation lazy-expiry checked on any `GET /bookings/:id` or `/remind`. Dates America/Guyana GMT-4.
- Config touched: `stage_checklists` (versioned; booked-entry gates), `dealer_taxes` (VAT/duty for fee invoice).

**🔀 Edge-of-edge cases → handling**

| Scenario | Detection | Handling | Owner | HITL? |
| --- | --- | --- | --- | --- |
| Two advisors book same VIN concurrently | `vehicles.status` row-lock; second `POST /bookings` sees `reserved` | `409 {vehicleStatus:'reserved'}`; loser offered next-available unit of same model | System / Sales lead | Yes (choose alt) |
| Fee payment declined / bounced (cheque, card) | `402` from payments; later cheque bounce flips invoice | Booking stays `active` but `reservationFeePaid=false`; advance blocked `422 reservation_fee`; retry payment (new idempotencyKey) | Sales Advisor | Yes |
| Idempotency replay (double-click fee) | Same `idempotencyKey` hits `idempotency_keys` | `200` returns original receipt; no duplicate ledger entry | System | No |
| Reservation soft-lock expires unpaid | Lazy-expiry on read / `/remind`: `now > expiresAt` | booking → `expired`, vehicle `reserved → available`, `holdUntil` cleared; lead phase reverts | System | No |
| Trusted bypass abuse (no manager approval) | Bypass without linked approval gate | Require `gates` entry; `bookingAmount=0` only with resolved waiver; else block | Sales Manager | Yes (gate resolve) |
| Dedup would merge two accounts each with assets | A1 sees both have `assets`/`deals` | A1 suppresses auto-merge; surfaces "manual review" task; keep separate | Sales Advisor | Yes |
| Cross-tenant customer link (CAM lead → GT customer) | `parentAccountId`/`customerId` dealer mismatch vs `activeDealerId` | `403`; query dealer-scoped, row invisible | System | No |
| Business account missing signatory contact | No `isPrimary` contact on `accountType=business` | Advance `422 primary_contact`; prompt to add signatory | Sales Advisor | Yes |
| WhatsApp confirmation opt-out / failed delivery | Outbox `email_logs` retry/backoff exhausted; opt-out flag | Fall back to email template; if opted-out, task advisor to call; log in `comm_notes` | System / Advisor | Yes (fallback) |
| Agent draft below confidence floor | `agent_runs.confidence < MIN_AGENT_CONFIDENCE` | Route to human — no draft auto-populated; advisor writes manually | System | Yes |
| Untrusted prior inbound text in brief | Inbound WhatsApp/email content in prompt | Wrapped with `guardUntrusted` before A7 call; injection neutralized | System | No |
| Kill-switch on (agent paused) | `agents.status='paused'` | Brief/dedup unavailable; advisor proceeds fully manual; UI banner | System | Yes |
| Trade-in appraisal not finalized | `deals.tradeInValue` null but claimed | Desking created with 0 trade; flagged; recompute on appraisal PATCH | Sales Advisor | Yes |
| Fee currency mismatch (paid GYD, stored USD) | Amount scale check vs `usdExchangeRate` | Convert on ingest to USD-scale; receipt shows both; no rounding drift | System | No |
| Duplicate booking for one lead | Active booking already exists for `leadId` | Reject second; offer amend existing `PATCH /bookings/:id` | Sales Advisor | Yes |

**📄 Documents & PDF format**

- **Reservation Receipt (PDF)** — generator: `pdfkit` via A3; delivery: `email_logs` outbox → WhatsApp/email (dedupeKey). Layout: *Header* dealer logo + name (CAM Motors / GT Automotive), division, address, TIN, receipt no. + date (GMT-4). *Buyer block* customer name/account, primary contact. *Body* single line: "Vehicle Reservation — {make/model/trim/year}, VIN {vin}". *Line-item columns* Description · Amount (USD) · Amount (GYD @ rate). *Totals* booking amount, method, balance-due-on-purchase note, `expiresAt`. *Footer* "Reservation fee applied to final OTD price; refundable per dealer policy" + payment/idempotency ref.
- **Reservation / Booking Confirmation** — WhatsApp/email template (nodemailer HTML): model, VIN, fee paid, hold-until date, advisor name, next steps. Human-approved via A7 before send.
- **Trusted-Bypass Waiver note** — no PDF; recorded as `gates` evidence + `customer_notes` with `waiverReason` and approving manager.
- **Deal Desking Sheet (screen, not PDF here)** — internal; `vehiclePrice`, `discount`, `tradeInValue`, server-computed `otdPrice`; PDF quote issued in Layer 5 (`/leads/:id/quote.pdf`).
