# Module C — Parts & Supply Chain Parts Advisor

**🚦 Flow (lowest level)**

- **Catalog / stock view** — Advisor opens Parts. `GET /api/parts` lists `parts` rows scoped by `activeDealerId(res)` + header `x-dealer-id` (dealer-scope EVERY query — CORRECTION). Columns: `sku`, name, `stock`, `reorderLevel`, `cost` (USD-scale), on-order qty, division. GYD cost shown = `cost × dealer.usdExchangeRate` (~209), rounded at display only.
- **Issue to a job card** — Technician/Advisor on an open `job_cards` row requests a part → `POST /api/job-cards/:id/parts` body `{partId,qty,move:"issue"}`. Server: (1) re-reads current `parts.stock` inside a txn, (2) if `stock < qty` → 409 backorder path, (3) decrements `parts.stock`, (4) inserts a `job_card_parts` row (`move:issue`, unitCost snapshot = `parts.cost` at issue time so historical costing is stable), (5) recomputes job-card parts subtotal, (6) emits `timeline_events` (domain=service, entity=job_card) + `activity`.
- **Return from a job card** — reversal (customer declined, wrong part, over-issued): `POST /api/job-cards/:id/parts` body `{jobCardPartId,qty,move:"return"}`. Server increments `parts.stock` back, inserts a paired `job_card_parts` row (`move:return`, negative-effect), never mutates the original issue row (append-only audit). Return qty is clamped ≤ net-issued for that job card.
- **Reorder trigger** — any stock-decrementing move (issue, or obsolescence write-off) evaluates `stock ≤ reorderLevel`. When crossed downward, the agent A-Replenish proposes an RFQ/PO draft (see Agents); the crossing itself writes a `notifications` row + a `tasks` row for the Parts Advisor. Purely deterministic threshold — no AI needed to detect.
- **RFQ → PO to supplier** — Advisor selects supplier and lines → `POST /api/part-purchases` creates a `part_purchases` header (`status`: draft→ordered) with lines `{partId,qtyOrdered,unitCost,expectedDate}`, `supplierId`. Money-affecting → wrapped with `idempotency_keys` (Idempotency-Key header). PO PDF generated via pdfkit (see Documents). Outbound RFQ/PO email queued to `email_logs` OUTBOX (retry/backoff/dedupe worker) addressed to `suppliers.email`.
- **Partial / full receipt** — goods arrive → `POST /api/part-purchases/:id/receive` body `{lines:[{lineId,qtyReceived}]}`. Server per-line: `qtyReceivedCum += qtyReceived` (never exceed `qtyOrdered`), increments `parts.stock` by received qty, updates weighted-average `parts.cost` = ((oldStock×oldCost)+(recv×poUnitCost)) / (oldStock+recv). Header `status` → `partially_received` while any line short, `received` when all lines fully in. Each receipt is its own idempotent event (partial receipts are additive, replay-safe).
- **Backorder resolution** — a receipt that lifts stock above 0 auto-scans `job_card_parts` rows flagged `backordered` for that `partId` (FIFO by createdAt), allocates, un-holds the linked `job_cards` (status back to `in_progress`), notifies the service advisor + customer via `email_logs`.
- **Supersession** — if a part is superseded (`supersededByPartId` set on the old `parts` row, `status:superseded`), any issue/PO for the old SKU transparently redirects to the successor SKU with an advisory banner; old SKU hidden from catalog picker but retained for history.
- **Obsolescence sweep** — scheduled agent flags no-movement parts (write-off proposal); human confirms → `PATCH /api/parts/:id` sets `status:obsolete` and, if writing off, a stock-adjust `job_card_parts`-style adjustment row records the loss (never silent).

**⚙️ Agents in play**

- **A-Replenish (Demand-forecast & auto-replenish)** — trigger: any move crosses `stock ≤ reorderLevel`, plus nightly cron. Grounded inputs (dealer-scoped): trailing issue velocity from `job_card_parts` (issue moves), `suppliers.leadTimeDays`, current `onOrderQty`, `reorderLevel`, `cost`. Output: a *draft* `part_purchases` (status=draft) with suggested qty = max(reorderLevel−stock+leadTimeDemand, 0). Autonomous-write agent → declared + every run in `agent_runs` (runType=replenish, confidence, latency). HITL: Parts Advisor Approve&Send converts draft→ordered; below `MIN_AGENT_CONFIDENCE` → no draft, only a `tasks` row for human to size manually. Kill-switch `isAgentEnabled` honored.
- **Obsolescence-sweep agent** — trigger: nightly cron. Inputs: no-movement window (no issue in N days) + stock value. Output: write-off *proposal* list surfaced as `notifications`/`tasks`; never auto-writes stock. Human confirms via `PATCH /api/parts/:id`. Records `agent_runs` (runType=obsolescence).
- **Supersession advisory** — deterministic (no LLM): when picker resolves a superseded SKU it substitutes `supersededByPartId` and annotates timeline. No autonomous money move.
- All agent free-text (supplier names, part descriptions from inbound supplier emails) passed through `guardUntrusted` before any prompt; PII-minimized; outputs id-validated against dealer inventory before display.

**🧠 AI for the persona**

- Replenishment sizing suggestion with rationale ("velocity 4/wk × 10-day lead = order 12; below-reorder by 5") — advisory only; deterministic threshold detection stays server-side, AI only sizes/explains.
- Obsolescence candidate ranking (slow-mover risk score) surfaced in `/dashboard/inventory-breakdown` — human approves each write-off.
- Concierge (`/api/anthropic` SSE, nav-only tools) answers "what's on backorder / below reorder" grounded strictly on dealer-scoped `parts`/`part_purchases` reads (grounding is dealer-scoped — CORRECTION).
- Never invents SKUs, supplier prices, or CIF/duty figures; unit costs come only from PO lines or existing `parts.cost`. Confidence below `MIN_AGENT_CONFIDENCE` routes to human, no draft PO.

**🔑 Key fields · validations · SLA**

- `parts`: `sku` unique per dealer (409 on dup); `stock` integer ≥ 0 (never allowed negative — backorder path instead); `reorderLevel` ≥ 0; `cost` USD-scale, GYD = `cost × dealer.usdExchangeRate` at display; `status` ∈ active|superseded|obsolete.
- `part_purchases` line invariant: `qtyReceivedCum ≤ qtyOrdered`; over-receipt → 422. Header `status`: draft→ordered→partially_received→received (cancelled allowed pre-receipt).
- `job_card_parts` append-only; return qty ≤ net-issued; issue snapshots `unitCost` so later cost changes don't retro-alter closed job cards.
- Weighted-average cost recompute on every receipt; write-offs record loss value, never silently zeroed.
- All money mutations (PO create, receive) idempotent via `idempotency_keys` + Idempotency-Key header; replays return the original result.
- SLA: below-reorder notification within same request as the crossing move; receipt reflected in stock atomically in-txn; RFQ/PO email delivery per OUTBOX worker retry/backoff; forecast cron nightly (America/Guyana GMT-4).
- Every row dealer-scoped by `activeDealerId`+`x-dealer-id`; audit-logs and object-storage (PO PDF) ACL also dealer-scoped (CORRECTION).

**🔀 Edge-of-edge cases → handling**

| Scenario | Detection | Handling | Owner | HITL? |
| --- | --- | --- | --- | --- |
| Issue qty > on-hand stock | in-txn `stock<qty` | 409 `{backordered,shortfall}`; create `job_card_parts` backordered flag, put `job_cards` on-hold, notify customer | Parts Advisor | No (auto) |
| Partial receipt then supplier cancels rest | PO stuck `partially_received` | close PO short (record variance), stock keeps received qty, re-trigger replenish for remainder | Parts Advisor | Yes |
| Duplicate receive POST (network retry) | same Idempotency-Key | return original response, no double stock increment | System | No |
| Concurrent issues on last unit | row-level txn on `parts.stock` | first commits, second sees updated stock → backorder path | System | No |
| Superseded part on an open PO | picker resolves `supersededByPartId` | receipt lands on successor SKU; advisory banner; old SKU history intact | System | No |
| Obsolete part still on a job card | sweep finds stock>0 linked to open jobs | block write-off; 422 until job cards resolved | Parts Advisor | Yes |
| Return exceeds net-issued | clamp check | 422; only net-issued returnable | System | No |
| USD cost changes after issue | snapshot on `job_card_parts` | closed job costing unchanged; only new issues use new cost | System | No |
| Replenish agent below `MIN_AGENT_CONFIDENCE` | confidence gate | no draft PO; human `tasks` row to size manually; run still audited | Parts Advisor | Yes |
| Agent kill-switch off | `isAgentEnabled=false` | all forecast/sweep drafting disabled; thresholds still fire deterministic notifications | Admin | Yes |
| Supplier email untrusted/HTML injection | inbound text | `guardUntrusted` wrap before any AI/display; never executed | System | No |
| Cross-dealer part lookup attempt | scope guard | 404 (scoped miss), audit-logged under caller's dealer | System | No |

**📄 Documents & PDF format**

- **Purchase Order PDF** (pdfkit, `GET /api/part-purchases/:id/pdf`): dealer header (division CAM/GT, address), PO number, supplier block, date (America/Guyana GMT-4), line table `SKU · description · qtyOrdered · unitCost(USD) · unitCost(GYD @rate) · line total`, subtotal/total in USD with GYD equivalent at `dealer.usdExchangeRate`, expected date, terms. Stored in GCS via presigned URL, ACL dealer-scoped.
- **RFQ email**: HTML template via nodemailer, queued to `email_logs` OUTBOX with dedupeKey, retry/backoff worker; PO PDF attached.
- **Goods-receipt note**: per-receipt record derivable from `part_purchases` receipt events (received qty, date, receiver, resulting weighted-avg cost) — printable audit trail.
- No tax on internal POs unless supplier is GYD-registered; any GRA/GYD tax figures come only from server-computed `dealer_taxes`, never AI-invented (CORRECTION — GRA = Guyana Revenue Authority).
