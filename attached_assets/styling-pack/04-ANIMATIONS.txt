04 · Motion & Animation
Two motion systems: (1) CSS keyframe utilities (in 02-theme.css ) for ambient and agent-driven effects, and
(2) framer-motion for list/enter transitions. The rule: motion is *purposeful and slow* — it signals state
change or system liveness, never decoration. Nothing bounces gratuitously; easing is gentle.

The "agent writes into a panel" choreography (signature moment)

When the agent populates a section, run these together to make it feel like the AI is physically filling the panel
in:
1. Panel mounts with agent-writing-overlay covering it.
2. agent-writing-scan line sweeps down (emerald glow).
3. Real children mount with agent-content-fade-in .
4. Panel gets a one-shot agent-just-populated emerald flash.
5. A "Agent just updated this" pill drops in with agent-pill-in .
This is the single most "alive" interaction — reproduce it for any agent write.

3. framer-motion usage
Imported as import { motion, AnimatePresence } from "framer-motion" . Used for:
Generative chart entrance — charts fade/scale in when the assistant produces them
( AnimatePresence so swapping chart kinds animates out/in).
List item enter/exit — activity feeds, message lists.
Standard entrance pattern:

<motion.div
initial={{ opacity: 0, y: 8 }}
animate={{ opacity: 1, y: 0 }}
exit={{ opacity: 0, y: -8 }}
transition={{ duration: 0.25, ease: [0.2, 0.8, 0.2, 1] }}
>

Keep durations 0.2–0.35s and use the same [0.2,0.8,0.2,1] ease everywhere for cohesion.

4. Transitions on state (the quiet majority)
Most "animation" is just transition-colors / transition-all on hover/active/width:
Sidebar collapse: transition-[width] duration-200 .
Progress bar fills: transition-all duration-500 on a style={{width}} div.
Hover states: transition-colors + the hover-elevate overlay system.
Confidence/score bars animate width changes smoothly via transition-all .
Principle: if a value changes, animate it ( transition-all ); if a surface is interactive, give it transition-colors
+ an elevate overlay. Never leave a state change instant.
