# Reference R7 — Integration Contracts

This reference gives the concrete wire contract for every external integration in **AURA**. Each entry states the exact request shape, the response/verification path, and the AURA-side handling. **Every** integration surface that touches data is dealer-scoped: inbound webhooks resolve `x-dealer-id` / division from the routing metadata before any write, presigned-storage ACLs carry the `dealerId`, and AI grounding (concierge, extraction, classification) is filtered to `activeDealerId(res)`. All untrusted inbound text (webhook bodies, email bodies, WhatsApp message text, transcript fragments) is wrapped with `guardUntrusted()` before it is ever placed in an AI prompt. Autonomous-write agents (A1 Intake/Dedup) run only when `isAgentEnabled(key)` is true, log via `recordAgentRun`, PII-minimize their input, and drop below `MIN_AGENT_CONFIDENCE` to a human queue.

## Meta Lead Ads webhook

| Phase | Contract |
| --- | --- |
| Verify (GET) | `GET /api/webhooks/meta?hub.mode=subscribe&hub.verify_token=&hub.challenge=`. Compare `hub.verify_token` to configured `META_VERIFY_TOKEN`. Match → respond **200** with the raw `hub.challenge` value (text/plain, echo). Mismatch → **403**. |
| Signature (POST) | Header `X-Hub-Signature-256: sha256=<hex>`. Compute HMAC-SHA256 over the **raw request body** with `META_APP_SECRET`; constant-time compare. Fail → **401**, no processing. |
| Body shape | `{ object: "page", entry: [{ id, time, changes: [{ field: "leadgen", value: { leadgen_id, page_id, form_id, ad_id, created_time } }] }] }`. The payload carries only `leadgen_id`, not the field answers. |
| Graph fetch | Fetch answers: `GET https://graph.facebook.com/v21.0/{leadgen_id}?access_token={PAGE_TOKEN}` → `{ id, created_time, field_data: [{ name, values: [] }], ad_id, form_id }`. Field names (full_name, phone_number, email, vehicle_of_interest, …) are mapped to `leads` columns. |
| Idempotency + dealer scope | Persist `webhook_events` keyed on `leadgen_id` (unique) — replays no-op. `page_id`/`form_id` resolve the target `dealerId` and `divisionId` before any lead write. |
| Downstream | Handoff to **A1 Intake/Dedup** (autonomous write, gated by `isAgentEnabled` + `recordAgentRun`). Creates or merges `leads` (`channel=meta_leadgen`, `source` from ad). Below `MIN_AGENT_CONFIDENCE` on a merge → human dedup queue. All fetched text `guardUntrusted`-wrapped. Ack **200** immediately; processing is async. |

## WhatsApp Meta Cloud API v21

| Phase | Contract |
| --- | --- |
| Verify (GET) | Same handshake as Meta: `GET /api/webhooks/whatsapp?hub.mode&hub.verify_token&hub.challenge` → echo `hub.challenge` on token match. |
| Inbound signature | `X-Hub-Signature-256` HMAC-SHA256 over raw body with app secret (as Meta above). |
| Inbound message body | `{ object:"whatsapp_business_account", entry:[{ id, changes:[{ field:"messages", value:{ messaging_product:"whatsapp", metadata:{ display_phone_number, phone_number_id }, contacts:[{ profile:{ name }, wa_id }], messages:[{ from, id, timestamp, type:"text"\|"interactive"\|"button"\|"image", text:{ body }, interactive:{ ... } }] } }] }] }`. Status callbacks arrive as `value.statuses:[{ id, status:"sent"\|"delivered"\|"read"\|"failed", recipient_id }]`. |
| Dealer routing | `metadata.phone_number_id` maps to the owning dealer; `wa_id` ties to/creates a `whatsapp_conversations` row scoped to that dealer. Message stored in `whatsapp_messages`; body `guardUntrusted`-wrapped before the guided-bot / A1 classifier reads it. |
| Outbound send | `POST https://graph.facebook.com/v21.0/{phone_number_id}/messages`, header `Authorization: Bearer {WHATSAPP_TOKEN}`. Session (<24h) text: `{ messaging_product:"whatsapp", to, type:"text", text:{ body } }`. Outside window: `{ ..., type:"template", template:{ name, language:{ code }, components:[] } }`. Response `{ messages:[{ id }] }` — the `wamid` is stored for status correlation. |
| Outbox | All sends go through the unified `email_logs` OUTBOX (email+WhatsApp) with `dedupeKey`, retry, and exponential backoff; a worker drains it. Idempotency prevents double-send on retry. |
| Ack | Return **200** within Meta's timeout; failed sends are the worker's concern, not the webhook's. |

## Twilio WhatsApp (alternate transport)

| Phase | Contract |
| --- | --- |
| Inbound signature | Header `X-Twilio-Signature`. Validate HMAC-**SHA1** (base64) computed over the full request URL concatenated with the sorted POST params, keyed by `TWILIO_AUTH_TOKEN`. Fail → **403**. |
| Inbound body (form-encoded) | `MessageSid, AccountSid, From=whatsapp:+<E164>, To=whatsapp:+<E164>, Body, NumMedia, ProfileName, WaId, MediaUrl0…`. `To` number maps to the dealer. |
| Persistence | `webhook_events` (type `twilio_whatsapp`, idempotency on `MessageSid`) + `whatsapp_messages`. `Body` `guardUntrusted`-wrapped. |
| Response | Reply with TwiML `<Response><Message>…</Message></Response>` for a bot turn, or empty `<Response/>` to ack silently and send later via the outbox. |

## Twilio Voice

| Phase | Contract |
| --- | --- |
| Access token mint | `GET /api/telephony/token` (auth required, dealer-scoped) → `{ token, identity }`. JWT AccessToken with a VoiceGrant (`outgoingApplicationSid`, `incomingAllow`), signed by API key/secret, short TTL. Client SDK uses it for the browser softphone. `GET /api/telephony/config` exposes provider (`twilio` vs `stub`) and whether the browser dialer is enabled. |
| Incoming call (POST) | `POST /api/webhooks/twilio/voice`, `X-Twilio-Signature` validated (SHA1). Form params `CallSid, From, To, CallStatus, Direction`. Respond TwiML that dials: `<Response><Dial action="/api/webhooks/twilio/voice/complete" ><Client>{identity}</Client></Dial></Response>`. |
| Completion (POST) | `POST /api/webhooks/twilio/voice/complete` with `CallSid, CallDuration, DialCallStatus, RecordingUrl`. Upserts `call_logs` (`provider=twilio`, `direction`, `duration`). Fires **A6 Call sentiment** fire-and-forget; sentiment is also refreshable via `POST /api/leads/:id/calls/:id/suggest-sentiment`. Transcript text `guardUntrusted`-wrapped before AI scoring; below `MIN_AGENT_CONFIDENCE` the `sentiment` stays null pending human. |
| Fallback | When provider is unconfigured, `StubTelephonyAdapter` serves `/telephony/config` and `call_logs` are created manually; no live TwiML. |

## Gmail inbound (IMAP intake)

| Aspect | Contract |
| --- | --- |
| Cadence | Worker polls IMAP every **2 minutes** per dealer inbox (auth via OAuth or app password from `emails/settings`). |
| Dedup | Each message keyed by RFC `Message-ID` into `webhook_events` (type `gmail_email`); already-seen IDs skipped. |
| Classify → lead | Subject + body (both `guardUntrusted`-wrapped, PII-minimized) go to **A1 Intake/Dedup** (claude-sonnet-4-6). AI classifies enquiry vs noise and extracts candidate name/phone/vehicle-interest. Autonomous `leads` create/merge (`channel=gmail_email`) only when `isAgentEnabled`; below `MIN_AGENT_CONFIDENCE` → human triage, no auto-create. Every run logged via `recordAgentRun`. |
| Scope | The polled mailbox belongs to exactly one dealer; the resulting lead inherits that `dealerId`/`divisionId`. Replies leave via the SMTP outbox (`email_logs`). |

## LOS — Demerara Bank finance connector

| Phase | Contract |
| --- | --- |
| Connector | Pluggable via `LOS_CONNECTOR`. Live = Demerara Bank REST; else sandbox DTI. `los_submissions.mode` = `live` \| `mock`. `GET /api/finance-connector` reports active connector + mode. |
| Submit | `POST /api/finance-applications/:id/submit`. Request derived from `finance_applications`: `{ amount, downPayment, termMonths, apr, bankId, applicant:{…PII-minimized}, vehicle:{ vin, price } }` — **amounts USD-scale** as stored (GYD only at display via `usdExchangeRate`). Records `los_submissions` (`event=submit`, `connector`, `mode`, `reference`, `payload`). Response `{ losReference, status }` stored as `finance_applications.losReference`; status moves `pending→submitted`, appended to `statusHistory[]`. `capital_order`/`credit_decline` may open a `gates` row. |
| Sync | `POST /api/finance-applications/:id/sync` (or worker) polls the LOS by `losReference`. Response `{ status, apr?, declineReason? }` maps to `submitted→under_review→approved\|declined→disbursed`; each transition appended to `statusHistory[]` and logged in `los_submissions` (`event=sync`). A `declined` result raises a `credit_decline` gate. |

## GCS presigned object storage

| Phase | Contract |
| --- | --- |
| Request URL | `POST /api/storage/uploads/request-url` req `{ fileName, contentType, module, entityId }`. Server (via Replit GCS sidecar) mints a presigned **PUT** URL. Resp `{ uploadUrl, objectPath, expiresAt, headers:{ "Content-Type" } }`. Client PUTs bytes directly to GCS. |
| ACL | The object path/ACL is stamped with the caller's `dealerId` and `module` via the ACL module — **every** object read/write is dealer-scoped. Cross-dealer access is denied even with a valid path. |
| Serve/download | `GET /api/storage/objects/*` resolves the ACL, then redirects to a presigned **GET** URL (short TTL) or streams. Document rows (`documents`, `customer_documents`, `finance_documents`) and `vehicles.images[]/documents[]` store `objectPath`, never public URLs. |
| Downstream AI | Uploaded docs feed **A5 Doc pre-fill** and **GRA vision extract** (`POST /api/gra/extract`) — see tax note below. |

## Anthropic — claude-sonnet-4-6

| Mode | Contract |
| --- | --- |
| Streaming (SSE) | `POST /api/anthropic/conversations` is the Concierge. Server calls Anthropic Messages API with `stream:true`, model `claude-sonnet-4-6`, and relays **SSE** (`content_block_delta` → token chunks). Grounding context is filtered to `activeDealerId(res)` — the concierge can only cite this dealer's data. Persists `conversations`/`messages`. User text and any retrieved records are `guardUntrusted`-wrapped. |
| Batch / synchronous | Agents (A1, A3 code path, A5, A6, A7, A10, A15, persona recommend, sentiment digest, GRA extract) call the Messages API non-streaming and parse a single JSON result. Every call: kill-switch `isAgentEnabled(key)` → `recordAgentRun` (`runType, input/outputSummary, confidence, latency, status`) in `agent_runs` → enforce `MIN_AGENT_CONFIDENCE` (below routes to human) → PII-minimize input. |
| GRA tax (correction) | GRA = **Guyana Revenue Authority** (GYD). AI **extracts legible fields only** from the document image; it never invents TIN/VIN/CIF/duty. The **server computes tax deterministically** from `dealer_taxes` (VAT 0/14%, import duty, EV duty exclusions via `excludeEv`), and a human `gra_filing` gate confirms before any `gra/filings` record. |

## CopilotKit runtime

| Aspect | Contract |
| --- | --- |
| Endpoint | `POST /api/copilotkit` — CopilotKit runtime backed by claude-sonnet-4-6. |
| Tool policy | **Nav-only**: the exposed actions are limited to client navigation (open a lead, deal, vehicle, deliveries board, report). No mutation, no money, no autonomous writes are wired as CopilotKit tools — write/approval flows stay behind their own dealer-scoped, gated endpoints. |
| Scope + safety | Any surfaced data is filtered to the active dealer; user prompts are `guardUntrusted`-wrapped. Kill-switch and audit apply as with any AI call. |
