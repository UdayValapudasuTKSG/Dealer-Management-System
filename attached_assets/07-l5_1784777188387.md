# Layer 5 — Vehicle Allocated Sales Advisor

**🚦 Flow (step-by-step, lowest level)**

- **1. Enter layer.** Lead is in phase where `selectedModel` (make/model/trim/year) is set but no physical `interestedVehicleId` VIN is bound yet. Sales Advisor opens the single **Workflow console** (Readiness-check view merged in — no separate "Run Review" screen per CORRECTION 6).
- **2. Inventory match.** `GET /api/vehicles?status=available&make=&model=&trim=&year=` — dealer-scoped by `activeDealerId(res)` + `x-dealer-id`, filtered to divisions the advisor may see (CAM/GT). Advisor sees the multi-inventory list of physical units matching `selectedModel`.
- **3. A11 VIN-allocation proposal.** On the deal draft, agent `A11` proposes the best `available` VIN for `selectedModel` (oldest holdUntil-free unit, division-matched). Below `MIN_AGENT_CONFIDENCE` → no auto-pick, routed to human list (CORRECTION 3).
- **4. Advisor selects VIN.** Advisor picks one physical unit; server validates `vin` (17) + `engineNumber` (17) + `registration` `^[A-Z]{3}[0-9]{1,4}$` against the vehicle row.
- **5. Soft-lock.** `PATCH /api/vehicles/:id` sets `status: reserved` (soft-lock) with `holdUntil` (SLA timer) + `holdReason`. VEHICLE_STATUS_TRANSITIONS guard rejects illegal jumps. Binds `leads.interestedVehicleId`.
- **6. Recall / damage monitor.** Selected VIN is checked against recall/damage flag on the vehicle row; if flagged, a `gates` row (advisory) surfaces and blocks the deal-commit CTA until cleared.
- **7. Readiness gate.** `POST /api/leads/:id/advance` — checklist gates (config-driven `stage_checklists`). Returns **422 `{unmet:[]}`** if VIN not allocated / recall open. Success advances stage and firms toward **Vehicle status → `booked`** at deal commit (Layer 6 VIN-lock via A11).
- **8. Timeline + audit.** Allocation writes a `timeline_events` row (per-lead + per-vehicle); A11 run recorded in `agent_runs`.

**⚙️ Agents in play**

- **A11 VIN allocation** → trigger: deal draft / advisor opens allocation on a lead with `selectedModel` → grounded inputs: `vehicles` rows WHERE `dealer_id`=active AND `status='available'` AND make/model/trim/year match, division-scoped; `leads.selectedModel`, `leads.divisionId` → output shape: `{vehicleId, vin, rationale, confidence}`, plus on commit performs VIN-lock (`vehicles.status→booked`). **HITL: yes** — advisor confirms the VIN; below `MIN_AGENT_CONFIDENCE` the agent proposes nothing and routes the full candidate list to the human. Deterministic post-step (VIN-lock) is not LLM. Kill-switchable via `agents.status=paused`; recorded in `agent_runs`.
- **A10 Test-drive / vehicle availability** → trigger: `GET /availability-check` → inputs: customer + selected `vehicles` row status/holdUntil (not advisor calendar) → output: `{vehicleAvailable,conflicts[]}`. **HITL: n/a** (read-only signal into the console).
- **A15 Pipeline suggestions** → trigger: `GET /pipeline/suggestions` → inputs: real leads in this phase → output: next-best-action cards ("allocate VIN for lead X"). **HITL: yes** — advisory only.

**🧠 AI for the persona**

- Ranked **VIN candidate list** for `selectedModel` with plain rationale ("oldest in stock, no hold, CAM division") — advisor clicks to confirm.
- **Recall/damage badge** on any candidate VIN so the advisor never allocates a flagged unit.
- Confidence chip on the A11 pick; when below floor the console shows "review manually — {n} candidates" instead of a pre-selected VIN.
- Availability signal (A10) inline so the advisor sees if the physical unit is already soft-locked elsewhere.

**🔑 Key fields · validations · SLA**

- `vin` = exactly 17 chars; `engineNumber` = exactly 17 chars; `registration` = `^[A-Z]{3}[0-9]{1,4}$` — server-validated on the vehicle row before lock.
- `leads.interestedVehicleId` bound to the chosen `vehicles.id`; `leads.selectedModel` must match the vehicle make/model/trim/year.
- **VEHICLE_STATUS_TRANSITIONS**: `available → reserved → booked → delivered/sold` (also `in_transit`, `service`); reverse/illegal jumps rejected 422.
- **Soft-lock SLA**: `holdUntil` timer (dealer-configured, America/Guyana GMT-4) with `holdReason`; on expiry lazy-release back to `available`.
- Config touched: `stage_checklists` (versioned) gate `vin_allocated` + `recall_clear`; `dealer_taxes` not touched here (tax at quote/deal). Money fields untouched (USD-scale; GYD = ×`usdExchangeRate`).
- Every read/write dealer-scoped (CORRECTION 1); untrusted inbound text on the lead (notes/WhatsApp) wrapped with `guardUntrusted` before display (CORRECTION 4).

**🔀 Edge-of-edge cases → handling**

| Scenario | Detection | Handling | Owner | HITL? |
| --- | --- | --- | --- | --- |
| Multi-inventory: several VINs match `selectedModel` | vehicles query returns >1 `available` | A11 ranks; advisor confirms one; others stay `available` | A11 + Advisor | Yes |
| Zero matching units in stock | vehicles query empty | Console offers `in_transit` units or "notify on arrival"; advance gate stays 422 `vin_allocated` | Advisor | Yes |
| Cross-showroom / other-division unit needed | match only in a division the advisor lacks or another dealer | Cross-tenant blocked (dealer-scope); cross-division surfaced as read-only "not allocatable here" — no bind | Server + Manager | Yes |
| Concurrency: two advisors lock same VIN | PATCH status write on already-`reserved` row | First write wins; second gets `409`, console re-fetches, prompts new pick | Server | Yes |
| Soft-lock (`holdUntil`) expired | lazy-expiry check on read/advance | Vehicle reverts `reserved→available`; `interestedVehicleId` cleared; advisor re-allocates; timeline event | Server + Advisor | Yes |
| VIN under recall / damage flag | recall/damage flag on vehicle row | Advisory `gates` row blocks deal-commit CTA; A11 excludes flagged VIN from proposal | Server + Manager | Yes |
| A11 confidence below floor | run `confidence < MIN_AGENT_CONFIDENCE` | No auto-pick; full candidate list routed to advisor; run logged `status=needs_review` | A11 → Advisor | Yes |
| Agent kill-switch active | `agents.status=paused` | A11 skipped; advisor selects VIN manually; audit notes agent-off | Advisor | Yes |
| Illegal status transition attempt | VEHICLE_STATUS_TRANSITIONS guard | `422`; state unchanged; error surfaced | Server | No |
| Bad VIN/engine/registration format | 17-char / regex validation | `422` validation error; lock refused | Server | No |
| selectedModel ≠ chosen vehicle spec | make/model/trim/year mismatch | Bind refused; advisor re-selects or updates `selectedModel` | Server + Advisor | Yes |
| Unit already `booked`/`sold` on another deal | availability-check (A10) conflict | Excluded from candidates; console shows conflict; no bind | Server | No |
| Vehicle deleted / moved mid-flow | 404 on re-fetch | Console clears stale candidate; advisor reloads inventory | Server + Advisor | Yes |
| Untrusted lead note injection | inbound text on lead | `guardUntrusted` wrap before AI/console render | Server | No |

**📄 Documents & PDF format**

- **Vehicle allocation summary** (screen card, no PDF at this layer) — VIN, engine number, registration, make/model/trim/year, price (USD-scale, GYD display ×`usdExchangeRate`), `holdUntil`, `holdReason`, division, recall/damage badge. Consumed in the Workflow console.
- **Quote PDF** (produced upstream by A3 via `pdfkit` `quote-pdf.ts`, delivered via email/WhatsApp outbox `email_logs`) is now VIN-bound. Layout: *header* dealer name/logo, `quoteNumber`, date (GMT-4); *vehicle section* VIN / engineNumber / registration / make-model-trim-year; *line-items* columns Description · Qty · Unit (GYD) · Amount; *tax lines* from `dealer_taxes` (VAT 0%/14%, duty — GRA Guyana, server-computed, never AI-invented); *totals* subtotal → tax → `total` in GYD; *footer* `validUntil`, status, dealer TIN.
- No delivery invoice / sales-order PDF is generated at Layer 5 — those are auto-created downstream at deal commit and delivery advance.
