# Platform P1 — Two-Portal Architecture & Tenancy Super Admin / Platform

**🚦 Flow (lowest level)**

- **Two physical portals, one API surface.** **Platform Console** (`/platform/*`, control-plane, super-admin) provisions and governs tenants; **Dealer Workspace** (data-plane, dealer-scoped) serves everyday DMS work. Both call the same Express+Drizzle API (163 OpenAPI paths → Zod → react-query); the plane is decided per-route, never by a second backend.
- **Request pipeline (ordered, server-side, every data-plane request):** (1) *session/auth* → no or invalid session ⇒ `401`; (2) *dealer-scope resolution* — read `x-dealer-id` and reconcile with the session's `activeDealerId` + caller memberships (`dealer_users`); (3) *RBAC* — role → `role_permissions.module` × category (see [#r4](#r4)); (4) *entitlement / feature-flag gate* (see INV-ENT-1, [#r9](#r9)); (5) *tenant lifecycle* — `dealers.status=suspended` blocks data-plane writes; (6) *idempotency* for mutations (see [#r4](#r4)); (7) handler executes inside dealer scope.
- **Dealer-scope resolution (NC-14, exhaustive):**
  - *Header present + caller IS a member* → scope bound to that dealer; proceed.
  - *Header present + caller is NOT a member* → `403` (authenticated but not permitted). This is a membership/authorization denial, not a hidden-row case.
  - *Header present + dealer id does not exist at all* → `403` (indistinguishable from "not your dealer"; no existence leak about the tenant table).
  - *Header ABSENT, data-plane GET* → default-dealer resolution: `lastActive` (session `activeDealerId`) → else *sole* membership → else return **picker payload** with `200` (list of memberships for the UI to choose) — **no error, never 404, never 401**.
  - *Header ABSENT, mutation, no resolvable active dealer* → `400` `dealer_required` (malformed/unresolvable dealer on a write). **Never 401 solely for a missing header.**
- **Cross-tenant isolation (NC-1, the core invariant):** once scope is bound, any resource id that resolves to a *foreign* dealer's row is treated as **not found within the active scope → `404`**. A foreign row NEVER returns `403` (that would leak its existence). `403` is reserved for "you asked for a dealer you're not a member of / RBAC denial"; `404` is reserved for "id not visible inside the dealer you ARE scoped to."
- **Tenant lifecycle intersect (see [#r2](#r2) for `dealers.status`):** `provisioning` (create default) → `active` (go-live checklist passed) → `suspended` (data-plane writes → `423`, reads still allowed) → `offboarding` → `closed`. Suspension is evaluated after RBAC/entitlement so a suspended-but-authorized caller still gets `423`, not `403`.
- **Impersonation flow (NC-10):** super-admin enters a tenant READ-ONLY by default, time-boxed ≤60m, reason required and logged, `impersonatedBy` stamped on `audit_logs`. Writes require explicit elevation; money-posting, gate-resolution, and customer-sends are HARD-BLOCKED even when elevated.

**⚙️ Agents / automation**

- **Deterministic SYSTEM actions** (plain code, NOT LLM, run inside the transactional flow, not kill-switchable): scope-resolver middleware (header ↔ membership reconciliation), RBAC evaluator, entitlement gate, idempotency store (`idempotency_keys`), suspension guard. None of these are agents; they are pipeline stages.
- **Provisioning is a SAGA** (NC-11): durable per-step markers + per-step compensation (create dealer row → seed roles/permissions → seed divisions → default entitlements → seed stage checklists). NEVER hold a DB transaction across an external call (GCS bucket setup / SMTP / LOS registration). `dealers.status` stays `provisioning` until every step succeeds; a failed step compensates and leaves the tenant non-go-live.
- **No autonomous AI writers operate in the control-plane.** The only autonomous LLM writers in AURA are A1 `intake_dedup`, A6 `call_sentiment`, A16 `case_classifier` (data-plane, internal-only, audited, kill-switchable) — see [#r3](#r3). Platform tenancy logic is fully deterministic.

**🧠 AI for the persona**

- The super-admin persona uses **no AI for tenancy or isolation decisions** — plane routing, membership, RBAC, entitlement, and lifecycle are pure code so behavior is auditable and reproducible.
- **Kill-switch governance (NC-13):** the per-agent kill-switch (`isAgentEnabled(semanticKey)`, keys: `intake_dedup, call_sentiment, case_classifier, doc_prefill, outreach, test_drive_availability, pipeline_suggestions, sentiment_digest, persona_recommend, concierge, gra_extract`) is a platform-reserved **'governance'** capability. It is NOT grantable via `/admin/roles` and is NOT the same as **settings:admin**. Toggling it is a control-plane action, audited like all platform mutations.
- All agent semantics live in [#r3](#r3); the catalog there IS complete — there is no "A1–A27" range.

**🔑 Key fields · validations · SLA**

- **Scope key:** `activeDealerId` (session) + `x-dealer-id` (header) must reconcile against `dealer_users` membership; dealer-scope is applied to EVERYTHING including concierge, audit, and storage reads.
- **Status-code contract (NC-1, verbatim):** `401` no/invalid session · `403` RBAC denial OR `x-dealer-id` not in memberships · `404` id not found within active dealer scope (foreign-row hiding) · `409` idempotency in-flight/dup OR write conflict · `422` validation / unmet stage gate `{unmet:[]}` / `key_reuse_mismatch` · `423` tenant suspended (writes blocked, reads allowed) · `429` rate limited (+ `Retry-After`) · `202` accepted async · `400` malformed / unresolvable dealer on mutation (`dealer_required`).
- **NC-14 missing-header rule:** data-plane GET → default-dealer resolution (lastActive → sole membership → else picker payload `200`); mutation with no resolvable dealer → `400` `dealer_required`; NEVER `401` solely for a missing header, NEVER `404` for a membership question.
- **INV-ENT-1 (NC-9):** a module/agent not entitled for the dealer returns `404` (hidden), enforced server-side after RBAC — not merely a hidden UI element.
- **Idempotency (NC-7):** every mutation requires `Idempotency-Key`; completed replay → stored response; in-flight dup → `409`; same key + different body → `422` `key_reuse_mismatch`.
- **Impersonation SLA (NC-10):** ttl ≤ 60m, read-only default, reason mandatory, `impersonatedBy` on every audit row; money-posting, gate-resolution, customer-sends HARD-BLOCKED.
- **Money/format:** USD-scale storage, GYD display × `usdExchangeRate` (~209); no payment gateway. These are data-plane concerns surfaced per-tenant.
- **Honesty scope (NC-12):** "foolproof" covers application-logic + tenant/money/AI invariants only. DR/backup, encryption-at-rest, HA/uptime, tracing, and message broker are PENDING-INFRA pre-GA blockers; this spec does NOT claim production/NFR readiness. [#r9](#r9) = defects in the BUILT app + corrected mandate (to-fix); V4 = residual open spec/infra items.

**🔀 Edge-of-edge cases → handling**

| Scenario | Detection | Handling | Owner | HITL? |
| --- | --- | --- | --- | --- |
| `x-dealer-id` points to a dealer the caller is NOT a member of | membership lookup miss in `dealer_users` | `403` not permitted (authorization denial, not existence) | scope middleware | No |
| Resource id belongs to another tenant while scoped to dealer A | row's `dealerId` ≠ active scope | `404` not found within scope — NEVER `403` (no cross-tenant existence leak) | scope middleware | No |
| Header absent, GET, multiple memberships, no `lastActive` | resolver finds >1 membership, no default | `200` picker payload (memberships listed) — no error | scope resolver | No |
| Header absent, mutation, no resolvable active dealer | resolver yields none | `400` `dealer_required` — never `401` | scope resolver | No |
| Header absent entirely, valid session | no `x-dealer-id` | NEVER `401`; route to default/picker (GET) or `dealer_required` (mutation) | scope resolver | No |
| Authorized member writes while tenant is `suspended` | lifecycle check post-RBAC | `423` on writes; reads still `200` | suspension guard | No |
| Authorized role hits a module not entitled for the dealer | entitlement gate after RBAC | `404` (hidden, INV-ENT-1) — indistinguishable from absent resource | entitlement gate | No |
| Impersonating admin attempts money-post / gate-resolve / customer-send | impersonation flag on session | HARD-BLOCK (403-class refusal even if elevated); reason-logged | impersonation guard | Yes (needs real dealer user) |
| Provisioning fails at external step (GCS/SMTP/LOS) | saga step marker not committed | compensate completed steps; `dealers.status` stays `provisioning`; no DB txn held across the call | provisioning saga | No |
| Idempotency key reused with a different body | stored request hash mismatch | `422` `key_reuse_mismatch` | idempotency store | No |
| Control-plane caller tries to grant the kill-switch via `/admin/roles` | reserved 'governance' capability check | Reject — not grantable as a role permission, distinct from **settings:admin** (NC-13) | platform RBAC | No |
| Burst traffic from one tenant | per-tenant rate counter | `429` + `Retry-After` | rate limiter | No |
