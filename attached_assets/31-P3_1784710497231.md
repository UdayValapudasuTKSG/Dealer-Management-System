# Platform P3 — Dealer Lifecycle, Entitlements & Offboarding Super Admin / Platform Finance

**🚦 Flow (lowest level)**

- **Canonical lifecycle (see [r2](#r2))** — `dealers.status`: **provisioning → active → suspended → offboarding → closed**. There is no other dealer state enum anywhere in the spec; every section REFERENCES this. Transitions are control-plane only (`/platform/*`, super-admin), each writes an `audit_logs` row + a `timeline_events` control-plane entry.
- **Create → provisioning.** `POST /platform/dealers` returns a dealer in **provisioning** (never **active**). Provisioning runs as a durable **SAGA** (see [r9](#r9) / NC-11): each step has a persisted marker + compensation; **no DB transaction is held across any external call** (GCS bucket/prefix create, LOS Demerara handshake, SMTP/WhatsApp sender verification). Dealer stays **provisioning** until the go-live checklist completes.
- **Go-live → active.** Super-admin runs the go-live checklist (divisions seeded, default roles + `role_permissions` loaded, at least one dealer admin in `dealer_users`, tax profile `dealer_taxes` + `usdExchangeRate`, entitlement plan bound). Checklist gate is a control-plane readiness check (NOT an [r2](#r2) gate type from NC-4). All-green → `POST /platform/dealers/{id}/activate` flips **provisioning → active**.
- **Suspend (active → suspended).** Money-affecting operation → default **advisory pre-check**: if the dealer has open money exposure (unpaid `invoices.status` ∈ {issued, partially_paid}, un-disbursed but approved `finance_applications`, open `gates.status=open`) the call returns **409** with an advisory body listing blockers. Caller may repeat with `{force:true}` to override → suspend proceeds. Once suspended: **data-plane writes blocked → **423****; **reads allowed** (agents/dealer users can still view). Control-plane remains reachable to un-suspend.
- **Resume (suspended → active).** `POST /platform/dealers/{id}/resume`. Reverses the write block; entitlements and RBAC snapshots are re-evaluated live (nothing cached past resume).
- **Offboarding (active|suspended → offboarding).** Begins tenant wind-down: writes blocked exactly as suspended (**423**), reads allowed for export window. Kicks a retention/export SAGA (whole-tenant export bundle to GCS presigned, retention-clock start per [r10](#r10)). Per-step markers + compensation; no transaction across GCS/SMTP.
- **Closed (offboarding → closed).** Terminal. After export delivered + retention obligations satisfied ([r10](#r10)), `POST /platform/dealers/{id}/close` flips to **closed**: all data-plane access hard-off (reads and writes), rows retained only per statutory retention then purged by the r10 job. Reactivation from **closed** is NOT supported (must re-provision).
- **Entitlements** are edited on any live dealer via `PATCH /platform/dealers/{id}/entitlements`; changes take effect on the next request (server-side gate, below).

**Status-code notes (NC-1):** control-plane endpoints are super-admin; **401** no/invalid session, **403** RBAC denial. Data-plane behavior for a suspended/offboarding tenant: reads **200**, writes **423** (tenant suspended, data-plane writes blocked). A data-plane request whose target module/agent is not entitled → **404** (hidden, per NC-9), never **403**. Missing `x-dealer-id` follows NC-14 (never 401 for the header alone).

**⚙️ Agents / automation**

- **Provisioning SAGA (deterministic system, not AI):** ordered steps — create dealer row → GCS prefix + presign policy → seed divisions → load default roles/`role_permissions`/`role_field_permissions` → bind entitlement plan → LOS Demerara sandbox handshake → sender (WhatsApp/SMTP) verification. Each step persists a marker in the saga record; failure runs the reverse compensation for completed steps. No LLM involved; not kill-switchable.
- **Offboarding SAGA (deterministic):** freeze writes (423) → build whole-tenant export bundle → deliver via GCS presigned → start r10 retention clock → on retention-satisfied allow **close**. Compensation restores **active**/**suspended** if aborted before close.
- **Suspend advisory pre-check (deterministic):** aggregates `invoices` (issued/partially_paid), approved-but-not-disbursed `finance_applications`, and `gates.status=open` into the **409** blocker list; pure code, no agent.
- **Entitlement gate (server-side, deterministic):** request pipeline order = auth → tenant-membership → RBAC → **entitlement/feature-flag** → handler. Not-entitled → **404**. See invariant INV-ENT-1 below.
- No autonomous AI writers operate in the control plane. The autonomous LLM writers (A1 intake_dedup, A6 call_sentiment, A16 case_classifier per [r3](#r3)) are all data-plane and dealer-scoped; suspending a dealer stops their writes via the same 423 write block.

**🧠 AI for the persona**

- Lifecycle actions are money/tenant-affecting and are **not** AI-driven — no LLM proposes, approves, or executes suspend/offboard/close. Advisory summaries shown to the super-admin (exposure rollup) are deterministic aggregates, not model output.
- **Kill-switch governance (NC-13):** per-agent enablement per dealer is edited through the entitlements `agents:{}` map, which is a platform-reserved **governance** capability — NOT grantable via `/admin/roles` and NOT the same as `settings:admin`. Runtime checks call `isAgentEnabled(semanticKey)` for keys: `intake_dedup, call_sentiment, case_classifier, doc_prefill, outreach, test_drive_availability, pipeline_suggestions, sentiment_digest, persona_recommend, concierge, gra_extract`. Deterministic system actions (A2 round_robin, A3 quote_tax, A11 vin_allocation) have no kill-switch.
- **Impersonation (NC-10):** super-admin impersonation is READ-ONLY by default, time-boxed (≤60m), reason-logged, audited via `impersonatedBy`. Writes require explicit elevation; money-posting, gate-resolution, and customer-sends are HARD-BLOCKED under impersonation regardless of elevation.

**🔑 Key fields · validations · SLA**

- `dealers.status` ∈ {provisioning, active, suspended, offboarding, closed} — canonical ([r2](#r2)); enforced transition table, illegal jumps → **409**.
- `region` ∈ {CAM, GT}; `usdExchangeRate` required > 0 (money is USD-scale, GYD display ×rate ≈209); `code` unique across platform.
- Entitlement keys are the exact RBAC module vocabulary (NC-5): `leads, customers, deals, quotes, bookings, inventory, billing, finance, deliveries, service, parts, gra, reports, dashboard, agents, communications, documents, search, settings, platform, audit`; agent keys = the kill-switch semantic keys above. Unknown key → **422**.
- **INV-ENT-1 (entitlements):** a module/agent not entitled for the active dealer is **hidden server-side** — the request returns **404** (never 403, no existence leak), enforced in the pipeline gate, not merely in the UI. UI hiding is cosmetic only.
- **INV-SUSP-1:** in **suspended** and **offboarding**, all data-plane mutations → **423**; reads succeed. In **closed**, both reads and writes are off.
- **Idempotency (NC-7):** every lifecycle mutation requires `Idempotency-Key`; completed replay → stored response, in-flight dup → **409**, same key + different body → **422** key_reuse_mismatch.
- **Honesty (NC-12):** lifecycle correctness (state machine, 423 write-block, entitlement 404, saga compensation) is application-logic "foolproof". DR/backup, encryption-at-rest, HA/uptime, tracing, and a durable message broker for the SAGAs are **PENDING-INFRA** pre-GA blockers; this spec does not claim NFR/production readiness.
- SLA: activate checklist eval <2s; suspend/resume effective immediately on next request; offboarding export bundle target ≤24h; impersonation session auto-expires at ttl (≤60m).

**🔀 Edge-of-edge cases → handling**

| Scenario | Detection | Handling | Owner | HITL? |
| --- | --- | --- | --- | --- |
| Suspend requested while unpaid invoices / undisbursed approved finance / open gates exist | Advisory pre-check aggregate | **409** with {blockers:[]}; proceeds only on repeat with {force:true} | Platform Finance | Yes — human must force |
| Data-plane write hits a suspended tenant | Pipeline tenant-status check | **423** tenant suspended; read of same resource still **200** | System | No |
| Provisioning SAGA fails at LOS/GCS/SMTP external step | Step marker error; no DB txn held across the call | Run compensations for completed steps; dealer remains **provisioning**; retry is idempotent | System | No |
| Activate called before go-live checklist green | Checklist evaluator | **422** {unmet:[]}; stays **provisioning** | Super Admin | Yes |
| Dealer user requests a module not in the dealer's entitlements | Entitlement gate (INV-ENT-1) | **404** hidden — never 403, no existence/leak signal | System | No |
| Kill-switch grant attempted via /admin/roles | Governance-capability check (NC-13) | Rejected — agent enablement is platform-reserved governance, not a role permission and not settings:admin | System | No |
| Impersonating super-admin attempts money-posting / gate resolve / customer send | Impersonation context flag | HARD-BLOCK even with elevation; audited under impersonatedBy | System | N/A |
| Impersonation session exceeds 60m | TTL expiry | Session auto-revoked; further calls → **401** | System | No |
| Per-customer erasure/export request arrives for a live dealer | Data-subject request (see [r10](#r10)) | Handled by r10 per-subject flow — distinct from whole-tenant offboarding export; does not change `dealers.status` | Privacy / Dealer Admin | Yes (r10) |
| Close called while export still delivering or retention clock active | Offboarding saga markers | **422** {unmet:[export_pending, retention_active]}; stays **offboarding** | Super Admin | Yes |
| Concurrent suspend + entitlement PATCH | Idempotency + row version | In-flight dup → **409**; both audited; entitlement re-evaluated on next request post-resume | System | No |

**📄 Documents / artifacts**

- **Provisioning saga record** — durable per-step markers + compensation log (control-plane).
- **Go-live checklist report** — unmet[] items resolved to green before activate.
- **Suspend/offboard advisory** — blocker rollup (open invoices, undisbursed finance, open gates) + force-override record.
- **Whole-tenant offboarding export bundle** — GCS presigned archive (distinct from r10 per-subject export/erasure artifacts; see [r10](#r10)).
- **Retention/erasure attestation** — produced by the [r10](#r10) retention job before **close**.
- **Control-plane audit trail** — `audit_logs` entries for every lifecycle transition, entitlement change, kill-switch toggle, and impersonation session (with impersonatedBy). No PDF template ([r8](#r8)) applies to lifecycle events.
